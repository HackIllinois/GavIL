# External review rounds

A change is not done until second agents have tried to break it (AGENTS.md rule 10, decisions #26, #40 and #71). This folder keeps the consensus list of each round: what the reviewers found, which findings held after they were checked against the code, and what was declined and why.

## How a round runs

1. A scratch copy of the repo goes to the reviewers. They read it, and run what they can, but change nothing in the repo.
2. **Reviewers.** Codex, Cursor (composer-2.5), OpenCode, Muse and Agy when they have quota. When a quota is out, the free OpenCode models (the default flint-40b, nemotron-3-ultra, deepseek, glm, mimo) and the Kilo CLI's free models take over. The final rounds used Sonnet reviewers by lens (web-security, web-ui, design-system).
3. **A refuter per finding.** For the final rounds an agent tries to knock each finding down against the current code. A finding it cannot refute goes into the consensus list; one it can is listed under "Refuted" with the evidence.
4. **Fix.** A held finding gets a failing-first test where it can be tested. A declined one gets its reason in the stage report, and the consensus file keeps the original claim.
5. **Free models are noisy.** Their findings are leads, not verdicts: the web-h2 list ends with items to ignore. The later reviewers re-checked any lead in their scope.

## Reading a consensus file

- `[n]` in the older lists is the number of reviewers that raised the item. Paths are relative to the folder the item names (`design-system/` in ds-d2, the repo root in the final lists).
- Severity bands are high, medium and low as the reviewer or verifier recorded them; the final lists also carry the verifier's own view, which was often lower.
- "Refuted" lists a claim and the evidence against it. Those are kept so nobody raises them again.
- The final web list was returned by the reviewer pool as text and recovered from the workflow's journal when the file was not written; its title is new and its absolute paths were made repo-relative. The raw reviewer outputs stay in the review run's scratch folder, not in the repo.

The builds of this run were each checked by independent verifier agents, up to three rounds, and the stage reports carry those verdicts. They are not external reviews, so they have no consensus file.
