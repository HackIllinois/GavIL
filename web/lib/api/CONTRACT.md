# Gav-IL ↔ adonix API contract

This file lists every endpoint the Gav-IL web app calls. It follows `docs/design-doc.md` §6–§9.

- Types live in `lib/api/types.ts`.
- The typed client is `lib/api/client.ts`.
- `lib/api/mock.ts` implements all of it in memory for `GAVIL_MOCK=1`.
- `lib/__tests__/mock.test.ts` checks the mock against the rules in this file.

adonix should implement these endpoints with its usual `specification({...})` and zod schemas. The OpenAPI doc (`/docs/json`) can then generate the client, the way `admin-site` uses `@hey-api/openapi-ts`.

## 0. Cross-cutting rules

**Transport**

- Gav-IL's Next.js server sends the adonix JWT as `Authorization: <jwt>`. The browser never holds it: it lives in our httpOnly `gavil_session` cookie (`SameSite=Lax`, **`Secure` everywhere but local development**: `secureCookies` in `lib/env.ts` treats an unset or unexpected `NODE_ENV` as a deployment, so a runtime that does not export it never sends a cookie over plain http; the same goes for `gavil_clear`, `gavil_scan`, `gavil_scan_pending`, `gavil_magic` and `gavil_oauth_state`). **adonix's base URL is a runtime setting** (CFX 11): `ADONIX_URL` (server-only, `wrangler.jsonc` `vars`; `NEXT_PUBLIC_ADONIX_URL` is still read as the old name) is read on every request by `adonixUrl()` in `client.ts`, never captured in a module constant, because a `NEXT_PUBLIC_` value read as `process.env.NEXT_PUBLIC_X` is frozen into the build by `next build` and a Wrangler `vars` override on a staging deploy would change nothing.
- A judging call with **no `Authorization` header** (the Gav-IL server sends none when the session cookie is gone, expired or forged) is `401`, never `403` or `404`: the judge's screen reads a 401 as "the session is over" (§3, CFX 2) and an adonix that answered differently would dead-letter the judge's work instead. The mock answers `401 Unauthorized` to every judging call without a session.
- Paths end in `/`.
- Errors look like `{ error: string, message: string, ...details }`.
- Times are ISO 8601. Money is whole US dollars.

**Roles**

- `ADMIN` and `STAFF` already exist. "STAFF" below means STAFF or ADMIN.
- `JUDGE` is new.

**Judge JWT claims (§7)**

- Judge tokens carry `role: "JUDGE"`, `eventId` and `assignmentId`, plus adonix's usual `id`, `email` and `exp`.
- They expire at the event's end time + 2 h, capped at 14 h. They do not use adonix's default 24 h.
- `POST /auth/refresh/` refreshes them only while the event is live.
- Gav-IL **verifies the session token on every request** before it routes or acts on it (S7): middleware (the `/judge` and `/admin` shells) and `getSession()` (every server action, route handler and page) call `verifySessionCached` (`lib/auth/verify.ts`): the mock signature, or the HS256 signature with `GAVIL_JWT_SECRET` (adonix's `JWT_SECRET`, shared), or else an adonix round trip (`GET /auth/roles/`, with the same 15 s timeout as every adonix call: a hung adonix is `unreachable`, never a stalled page), plus `exp` present, not passed and capped. One verdict per token is reused for up to 60 s per server isolate (never past `exp`; "unreachable" is never cached). A cookie that only decodes is no session: a forged one is cleared and never opens a shell. Revocation stays adonix's, on every API call (below).

**Revocation is immediate**

- Every `/judging/*` call by a JUDGE does one indexed read of `JudgeAssignment.revokedAt` for the token's `assignmentId`.
- If `revokedAt` is set, adonix answers `401 { error: "Revoked" }`.
- A JWT that is still unexpired stops working the moment an admin presses **Revoke**. Gav-IL then signs the phone out (`/login?error=revoked`, §3).

**Origin check on writes**

- adonix rejects every non-GET request whose `Origin` header is missing, or does not match the allow-listed Gav-IL origins (the same hosts as `ALLOWED_WEB_HOSTS`). The rejection is `403 { error: "BadOrigin" }`.
- Our server sends `Origin` on every write, never on a GET (`AdonixClient` takes it as its `origin` argument). `getApi()` picks it with `writeOrigin` (`client.ts`): `GAVIL_ORIGIN` is the allow-list (one origin or a comma-separated list); the request's own origin is sent only when it is on that list, otherwise the first entry, so a forged `Host` header never chooses it. Without `GAVIL_ORIGIN` only local development (`next dev`, vitest) uses the request's host: **a deployed build with no usable `GAVIL_ORIGIN` serves nothing** (`assertOrigin` in `getApi()` throws on every request, `originProblem` in `lib/env.ts`; checked per request, not at boot, because a runtime may fill `process.env` only when a request arrives), and the staff Google callback (`publicOrigin`) likewise never falls back to `Host` / `X-Forwarded-Host`. Every adonix call also has a 15 s timeout (`ADONIX_TIMEOUT_MS`), after which the phone queues the write.
- Gav-IL's own POST route handlers check `Origin` against the host too (`lib/auth/origin.ts`). Next.js does the same for server actions.
- Auth pages send `Referrer-Policy: no-referrer`, and under that policy browsers post forms with `Origin: null`. A null or missing `Origin` is accepted only when `Sec-Fetch-Site: same-origin` (Fetch Metadata, which page script cannot set).
- Our own POST routes and the highlights action check the browser's `Origin` with `sameOrigin` (`lib/auth/origin.ts`): it must name this site's **host and scheme** (the host is the first entry of `X-Forwarded-Host`, since a proxy may send a list; an `http://` origin for an `https` site is refused; with only headers to go on, as in a server action, only `https` counts, or `http` in local development), or be on the pinned `GAVIL_ORIGIN` list.

**Idempotent writes**

- Every judge write (arrival, evaluation, skip, vote, Round 2 ranking) carries a client-generated `clientId`, and so does a team check-in.
- adonix keeps a unique index on **`(eventId, judgeId, clientId)`**. A replayed write returns the original result with `200` and changes nothing.
- The stored write keeps its content (not its timestamps). The same `clientId` with **different content** is `409 ClientIdReused` and changes nothing; it is never silently dropped. A vote's content is its pair, so a resent vote on the same pair returns the first vote whichever way it was cast.
- A replayed arrival never counts a wrong code twice and never tasks staff twice. An arrival's `clientId` is scoped to its judge, **its visit and its content** (method, code, check; never its times or token, so a replay sent after the scan grant was spent is the same arrival): the same id for another visit or other content is `409 ClientIdReused` and changes nothing (S22). A team check-in **must** carry a `clientId` (`400 BadInput { field: "clientId" }` without one, S12); a replayed one for the same table returns its first result (it can't clear an absent report made after it), and for another table is `409 ClientIdReused`.
- This is what makes the phone's offline outbox safe to replay.
- **Retention (CFX 13).** An idempotency key is kept for **36 h from its first use** (`IDEMPOTENCY_RETENTION_MS`): inside it a replay is a no-op (or `409 ClientIdReused` for other content); after it the id is forgotten, and nothing legitimate replays a day later (the phone replays within minutes). A key is **never evicted early**: each memory (a judge's writes by `clientId`, arrival ids, Table talk receipt uses, table check-ins) holds at most `MOCK_MEMORY_MAX` = 20 000 keys, and at that limit a **new** key is refused with `400 TooManyWrites` and changes nothing, instead of an old one being dropped (which would let an old replay count a second time). The mock models it (`admit`, `recalled`, `remember` in `mock.ts`); adonix gets it from its unique index plus a TTL on it. Spend nonces and spend attempts expire by their own times (§6).
- Every endpoint is **one atomic operation** (one transaction or `findOneAndUpdate`): nothing another request does can land between its checks and its writes. The mock models this: its endpoints do all their work synchronously, except an evaluation, which awaits the Table talk receipt check (Web Crypto) and then **re-runs every check** (the judge not revoked, room, hold, conflict, nominations, its own visit at the table) **in the same synchronous block as its commit**. A request with a `clientId` that is still in flight is claimed before it starts: a concurrent duplicate waits for it and gets its result (a double tap never counts a project twice or puts it twice in the compare chain). A concurrent second evaluation of the same project with another `clientId` lands as an edit of the first (or as nothing when its content is the same). adonix does the same with a unique `(eventId, judgeId, clientId)` insert inside the evaluation's transaction. The seeded simulation interleaves 8 judges' calls (with double submits) to check it.

**Every state-changing judge write names its judge (`judgeId`)**

- Arrivals, evaluations, skips, votes, drafts, Round 2 rankings, renew/defer, the in-app scanner and help carry `judgeId` in the body: the judge the phone (or tab) thinks is signed in (`JudgeScoped` in `types.ts`).
- adonix compares it with the JWT's judge. A mismatch is **`409 WrongJudge`** and changes nothing: a stale tab, or an outbox item saved by another judge on a shared phone, is never applied as whoever is signed in now. The phone **holds** a `WrongJudge` item: it stays queued and goes when its own judge is back.
- **Where this stands today** (H-client). The web client sends `judgeId` on every write above: `EvaluationInput`, `SkipInput`, `VoteInput` and `Round2Input` extend `JudgeScoped` (`Round2Input` also carries `createdAt`/`sentAt` on outbox replays), and `checkIn`, `arriveAt`, `renewVisit`, `deferVisit`, `saveDraft` and `requestHelp` take a trailing `JudgeScoped` / options argument that `AdonixClient` puts in the body. Every judge server action (`app/judge/actions.ts`) takes the judge the screen was rendered for (or the one an outbox item was saved under), refuses it with `409 WrongJudge` before calling adonix when the session is someone else, and forwards it. The mock checks it whenever it is sent; adonix should accept a missing one only until every deployed build sends it, then make it required (`400 JudgeRequired`).
- The phone keeps one outbox per judge (`gavil:outbox:v3:<eventId>:<judgeId>`) and Gav-IL's server actions refuse a replay saved under another judge before it reaches adonix. A `WrongJudge` holds the queue ("This phone is signed in as someone else", shown only on the screens of the judge whose write was refused; nothing is deleted); an item found in another judge's queue is moved back to its own judge's queue. A write whose send fails while the phone thinks it is online (fetch throws, the 15 s `ADONIX_TIMEOUT_MS`, 5xx, 408, 429) is queued like an offline one. The phone itself waits at most 12 s for any judge write's answer, online or replayed (`SEND_TIMEOUT_MS`, `lib/outbox.ts`): venue Wi-Fi that drops packets never fails a request, so no answer in time also queues the write ("Saved on this phone"), a flush always ends, and sign-out's "Send first" can't hang. Next.js runs server actions one at a time, so while a send is still out the phone never sends a second copy of that write behind it; once it answers the item is resent (a no-op if it landed, every write carrying its `clientId`). Other permanent 4xx refusals go to a visible dead-letter list (with code and status, for staff), which a later success for the same table, pair or prize settles; network errors, 5xx, 408 and 429 back off 2, 4, 8 … 60 s.

- **What "saved on this phone" promises** (W3; `lib/outbox.ts`). A write counts as saved only when the phone really holds it afterwards: the store is read back after the write (a full or blocked `localStorage`, and the no-op store of a browser with storage off, both fail that check), and the queue is capped at `QUEUE_MAX` = 500 items (drafts and Round 2 rankings collapse, a replaced item takes its predecessor's place, so only a new write past the cap is refused). A write that can be neither sent nor kept comes back as `unsaved` (`storage` or `full`), never `queued`: the screen says "Your evaluation may not have reached the server, and it couldn’t be saved on this phone either. Keep this screen open and try again", the notes stay in front of the judge, and nothing reads "saved". **A resubmit that is refused** (a final answer: `NotesTooLong`, `NotArrived`, …) removes the queued item it replaced, so the older notes never replay behind the judge's back; a retryable failure still replaces it in place, and while the newer write is out the older copy is marked `supersededBy` so a flush (the retry timer, another tab) waits for it instead of replaying the old words over the new. A flush also stops (and retries later) when the store refuses to drop a sent item, rather than sending it in a loop. **An expired session (CFX 2):** the end of a session is answered as DATA by every write action (`submitEvaluation`, `skipProject`, `castVote`, `submitRound2`, `saveDraft`, `deferVisit`, `arrive`) and the two calls that fire by themselves while the judge types (`pollStatus`, `renewVisit`): `401 { code: "SessionEnded" }` (or `Revoked`, adonix's own word for a removed judge), never a `redirect()`. Next.js applies a server action's redirect to the router the moment the action answers (`serverActionReducer` sets the new canonical URL and tree; nothing the screen does with the rejection stops it), so a redirect leaves the judge's screen whether or not the phone could keep the write, and a full or blocked `localStorage` would take the evaluation they just typed with it. So the route gate lets a judge's server-action POST with a dead session (expired, no cookie, forged) through to the action instead of answering it with `303` + `x-action-redirect` (the admin console keeps that answer; page requests still get the `307`), and the actions **touch no cookie** when they answer it (Next.js re-renders the page after an action that sets or deletes one, and with no session that page redirects). `deliver` then keeps the write first (`enqueueChecked`, read back): kept, it returns `queued` with `why: "signed-out"` and the screen leaves with a hard navigation to `GET /auth/logout?next=<page>&error=expired` (`signInPath`, `leaveForSignIn`), the route that checks the session really is dead, clears the cookie, names the judge for `/login` and lands there; **not kept, it returns `unsaved` with `sessionEnd`, the screen does NOT leave**, the words stay in front of the judge, and every judge screen shows "Your session ended" with a "Sign in again" button (`OutboxAlert`, `flagSessionEnd`). A flush that meets the same answer ends with `signedOut` + `sessionEnd` (nothing is dead-lettered or retried on a timer; everything stays queued) and the hook leaves the same way, or says so if the phone can't keep what is on the screen. `/login?error=expired` keeps the unsent queue AND the notes typed but not yet sent AND the memory of votes already sent (a revoked judge, a sign-out and "Not Sarah?" still clear them); it says "Anything saved on this phone sends once you do". The check-in button and the help request (nothing typed to lose) still redirect from the action. A poll or renewal that meets it leaves the same way as a flush (`leaveForSignIn`), or, if the phone can't keep what is on the screen, shows the alert. **The offline banner** says "your work is saved on this phone" only when the phone can keep a write (`storageWorks()`, a write-and-read probe of `localStorage`, re-run when the outbox changes); with storage blocked or full it says "This phone can’t keep your work. Keep this page open: it sends when you reconnect", so the screen never contradicts the "couldn’t be saved on this phone either" error under it. **A check-in's `clientId`** is derived from the visit, the method and a hash of the code and the typed check (`arrivalClientId`): the same attempt after a reload or a second tap is the same id (queued once; adonix's `(judge, visit, content)` rule counts it once), another code or check is another id; the QR scan uses the grant's own id instead (`grantClientId`). Every write for a table, "can’t find it" included, waits in line behind that table's own queued check-in. **Not done, on purpose:** the queue is not encrypted at rest (a key would have to live in the same browser; a shared phone is handled by "Delete them and sign out" and by never replaying another judge's items), and `/t` has no app-level rate limit (a signed-out scan makes no API call and keeps no server state; per-IP limits belong on the edge).
- **The outbox's other promises (CFX).** (1) *A refusal is kept before the item leaves the queue*: when a send gets a permanent 4xx, the flush writes the dead letter and **reads it back first**; if the phone can't hold it, the item stays queued, the flush stops with `FlushReport.storageError` and retries (2, 4, 8 … 60 s), every judge screen says "This phone can't save right now" (`OutboxAlert`), and Compare's Continue answers "storage" instead of waving the judge on past a vote nobody has an answer for. An online refusal's `dead: true` means the phone really kept the dead letter. (2) *An expired session never discards a write the phone could not keep*: the write actions answer a dead session as data (above), `deliver` queues the write before the screen leaves, and if the phone can't hold it returns `unsaved` and the screen stays (the check-in path does the same, `keepWrite`); a thrown navigation (any other redirect an action starts) is still queued first and rethrown only when kept. (3) *The room's words leave the phone*: a queued evaluation's transcript (`talkProof`) is taken out of **storage** when its receipt runs out (`talkExpiresAt`, else 30 min after the tap): at every flush, every enqueue, every screen load and **at the moment it expires** (`talkExpiryWatch`), together with the verbatim `quote` of each kept highlight (the highlight itself stays, the server reports it dropped and the judge is told); a refused item keeps the judge's notes but **no transcript, no quotes and no highlights**. (4) *No placard token is ever stored or replayed*: an arrival an older build saved with `k` loses it when read, is written back without it, and is refused at the next flush as `422 ScanExpired` ("Check in again with a fresh scan or a typed check") instead of being replayed. (5) *Two tabs of one judge don't overwrite each other*: **every** change to the judge's stored queue, dead letters and notices made from an async path runs inside one **Web Lock** per judge (`navigator.locks`, `exclusive`), held only for a synchronous change and never across a network call: the enqueue, the flush's whole step after a send (dead letter, removal, settling, notice, retry count), `deliver`'s supersede mark, removal and dead letter, the tidy and the expiry sweep (also the screen's timer), the move of a stray item to its owner's queue (both judges' locks, always taken in one order, so two tabs can't wait on each other), and the helpers the screens call (`settled`, `dismissDeadItems`, `dismissNotices`, `noteTalkDropped`, `dropQueued`). Taking the lock is where a tab reads what the other wrote: a plain localStorage read in one tab can lag another tab's write (measured in Chromium), so a re-read before writing, which every change also does (`mutate`), narrows the window but **does not close it**. Without Web Locks (an insecure page, an old browser) that re-read is all there is, and a lost write is possible; the deployed site is https on browsers that have them. The two writers that cannot wait for a lock, `enqueue` and `enqueueQuietly` (a page being hidden or closed writes at once), have only the re-read; drafts (`gavil:drafts`) and the sent-vote memory (`gavil:sent`) are last-writer-wins per key by design and never hold a judge's submitted write, and a deliberate discard (`discardJudge`, `clearPhone`: the judge confirmed "delete") removes whole keys at once, unlocked, because it must finish before the page navigates. (6) *The room's words, second pass*: a receipt already dead at Submit writes the highlight without its quote (`evaluationWrite`), and quotes with no transcript behind them are swept at the next tidy rather than after 30 minutes; a refused old scan (a dead letter) loses its placard token `k` like a queued one (`readDead`, rewritten by the tidy).

**Bodies are validated before anything else**

- Every judging write checks its field types first (adonix: its zod schemas): a missing required string, a number where a string goes, `nominations` / `order` that aren't an array of ids, a non-boolean `queued`. A wrong type is **`400 BadInput { field }`** and changes nothing, never a 500: the phone dead-letters a malformed outbox item instead of retrying it forever. (`expectShape` and `arrivalInputProblem` in the mock.)

**Write times: the server's clock, bounded (server time anchor)**

- A write sent the moment it is made (an online submit, skip or arrival) omits `createdAt` and is **stamped by the server**.
- A write the phone saved for later (offline, or a vote after its undo window) carries `createdAt` (phone clock at the tap) and **`sentAt`** (phone clock when the request left the phone). adonix moves the stamp onto its own clock: `createdAt + (server now − sentAt)` (`serverTime` in `lib/judging.ts`), so a phone clock that runs fast or slow never makes a write look early, late or in the future.
- The corrected time is **honoured only within bounds** (`clientTime` in `lib/judging.ts`): at most 2 min in the future (else `400 BadTime`); at most **2 min old** for a write sent online, or **20 min old (`MAX_OFFLINE_SECONDS`) for an outbox replay** (`sentAt` present, or an arrival with `queued: true`). An older claim is **not honoured**: the server stamps the write with its own clock, so nobody can backdate work into an expired lease or the grace window by claiming a long offline spell (a forged `sentAt` shifts the stamp, but never more than 20 min back).
- An honoured time must not be before the round started or before what it follows (an evaluation: the judge's arrival at that table; a vote: both evaluations it compares; an edit: the first version), each with 2 min of skew (`400 BadTime`).
- Deadlines (`409 RoundOver`): a first evaluation, a vote, a busy/conflict/other skip and an arrival by Round 1's end + the 15-min grace window (the table the judge is at, and its comparison); **an edit of an earlier evaluation, a draft of one, and an absent report by Round 1's end** (finalists come from nominations, so they can't change once Round 2 opens, and nobody is sent to an absent table after the end). Round 2 opens when nominations close, **Round 1's end + the 15-min grace** (`Round2Board.opensAt`), the same moment a first evaluation, a judge's own proof and staff's Done on a placard task stop adding nominations, so nothing can add a finalist after a judge may rank. A Round 2 ranking by `RoundState.deliberationEndsAt`. A write replayed later counts when its honoured time was in time.

**Votes: undo happens on the phone**

- The 8 s undo is entirely client-side. A vote is only sent after the undo window closes, so adonix never holds a "pending" vote and there is no undo endpoint.
- A vote that arrives after Round 1 ends is accepted if its honoured `createdAt` (see the write-time bounds above) was before the end of the grace window, and not before the two evaluations it compares. Past the grace window no comparison is offered (`/compare/` is null, `/next/` and `/progress/` say `time-up`), so a judge is never routed to a vote that can't count.

**Privacy: Table talk (§6)**

- No audio is ever stored, by Gav-IL or adonix. Audio exists only in memory for the one transcription request and is dropped right after.
- No diarization, no speaker labels, no voice embeddings, no matching voices across recordings (Illinois BIPA voiceprints). Who said what is inferred from wording only, or `"unknown"`.
- Transcripts: Gav-IL stores none and never logs one. If adonix ever keeps one for dispute review, it goes in its own `TalkTranscript` collection, readable only by that judge, with a TTL index `expireAt = event end + 7 days`, never exported and never shown to sponsors, other judges or admins. The default is not to keep them.
- Only highlights a judge kept travel, inside the evaluation, and follow the notes' retention.
- Off by default per event (`EventSettings.recordingEnabled`) until HackIllinois / UIUC counsel signs off.

**Vocabulary**

- **Path** = `"pro" | "general"`.
- **Track** = the company track string on a project.
- **Prize** = a HackIllinois, company or MLH award.
- Judges *nominate* and *compare*. "Score" is admissions-only.

## 1. Auth (`/auth`)

### Existing, used as-is

| Method | Path | Role | Request | Response |
|---|---|---|---|---|
| GET | `/auth/login/google/?redirect=<url>` | public | browser redirect | 302 to Google, then to `redirect` with the JWT as the `jwt` cookie (web) or `?token=` (allow-listed mobile) |
| GET | `/auth/token/` | USER | `jwt` cookie | `{ jwt }` |
| POST | `/auth/refresh/` | USER | — | `{ jwt }` (judges: only while the event is live) |
| POST | `/auth/logout/` | USER | — | `{ success: true }`, clears adonix's cookie |
| GET | `/auth/roles/` | USER | — | `{ id, roles: Role[] }` |

**Staff flow**

1. "Sign in with Google" links to Gav-IL's **`GET /auth/google?next=/admin`**, which mints a one-time `state` nonce (32 random bytes), keeps it in an httpOnly `gavil_oauth_state` cookie (path `/auth`, 10 min), and redirects to `GET {adonix}/auth/login/google/?redirect=https://<gavil>/auth/callback?next=/admin&state=<nonce>`. `<gavil>` comes from `GAVIL_ORIGIN` read as an allow-list, like the write Origin (`publicOrigin` in `lib/auth/cookie.ts`, `writeOrigin`): the request's own origin when it is on the list, otherwise the first entry, so a list never ends up in the callback and a forged `Host` never picks it. `next` never carries a bearer value (`safeNext` drops `k` and `token` and keeps only the code in `at`).
2. adonix runs Google OAuth and redirects back to that URL.
3. `/auth/callback` installs a session only when **all** of these hold, and otherwise sends the browser to `/login?error=callback|token|network` with no cookie set:
   - `state` equals the nonce cookie (constant-time compare); the nonce is then deleted. This stops login CSRF: a link to `/auth/callback?token=<someone else's token>` signs nobody in. A callback with no `state` at all (an old link) starts over at `/auth/google`.
   - The token (from `?token=` or adonix's `jwt` cookie) is **verified server-side** (`lib/auth/verify.ts`): with `GAVIL_JWT_SECRET` (adonix's `JWT_SECRET`, shared) an HS256 signature check; otherwise an adonix round trip, `GET /auth/roles/` with the token, which must answer 200 with the same user id and every routing role the token claims (ADMIN, STAFF, JUDGE). Decoding alone never installs a session.
   - The token has `exp`, is not expired, and does not claim to live longer than the caps (judge 14 h, staff 24 h, plus 5 min of skew). A token without `exp` is never accepted, anywhere (middleware treats it as expired).
4. The session cookie (`gavil_session`, httpOnly, Secure in production, SameSite=Lax) holds the token; the response is no-store, no-referrer.

Mock mode stands in for adonix, behind **one fail-closed gate** (`mockEnabled()` in `lib/env.ts`, S6): `GAVIL_MOCK=1` **and** `NODE_ENV` is `development` (`next dev`) or `test` (vitest). `next start`, a Cloudflare deploy and an unset `NODE_ENV` are never mock, whatever `GAVIL_MOCK` says; every dev secret (the mock JWT secret `GAVIL_MOCK_SECRET`, the placard secret, the scan-grant secret, the talk receipt secret) and the fixture transcription sit behind it. A **boot-time assertion** (`instrumentation.ts`, repeated by `getApi()` on every request) refuses to run a server with `GAVIL_MOCK=1` or `GAVIL_MOCK_DEMO=1` outside development/test. Mock tokens are HS256-signed with the dev secret, and the decoder refuses any other token, so a hand-made cookie never reaches the mock API as a judge or an admin.

Mock-only demo shortcuts (`mockDemoShortcuts` in `mock.ts`, `mockDemoEnabled` in `lib/env.ts`): every email code is `123456` and `/auth/magic?token=demo-<judgeId>` is a one-time sign-in link. They are on **only with an explicit `GAVIL_MOCK_DEMO=1`** in mock mode: never by default, not even under `next dev`, never in the tests or a deployed build. Every limit still applies to them. **adonix has neither.**

**Every JWT a judge sign-in returns is verified before it is installed** (S8, `verifyJudgeToken`): the code login (`app/login/actions.ts`) and the link / desk-QR redeem (`/auth/magic/redeem`) run `verifySessionToken` (signature or round trip, `exp` capped) and require a `JUDGE` token with `eventId` and `assignmentId`. A staff token, an unsigned or an overlong one installs nothing (`/auth/magic?state=error`).

**Bearer tokens leave the URL on arrival** (S18): `/auth/magic?token=…` is answered by middleware with a 303 to the bare `/auth/magic`, the token moved into an httpOnly `gavil_magic` cookie (path `/auth/magic`, 15 min); the confirm page and Continue read it. `/auth/callback?token=…` installs the session and 303s away in the same response (a redirect never stays in the history). The placard `k` is swapped at `/t` (§2). Gav-IL never logs a URL; the hosting platform's request logs must drop query strings (Workers Logs / Logpush field filter), since the first request of each flow still carries its token.

Requirements on adonix: the Gav-IL host must be in `ALLOWED_WEB_HOSTS`, the `redirect` URL (with its `state`) is passed through unchanged, and Google accounts must be `@hackillinois.org`.

### New: judge passwordless sign-in

This is modelled on the existing sponsor code flow (`/auth/sponsor/verify` and `/auth/sponsor/login`), using the same `AuthCode` model.

- **Emails and tokens are always in the request body, never the query string**, because adonix logs URLs.
- Gav-IL auth pages send `Referrer-Policy: no-referrer`.

| Method | Path | Role | Request | Response |
|---|---|---|---|---|
| POST | `/auth/judge/verify/` | public | `{ email }` | `{ success: true }` for any well-formed email, within the limits (see below): `400 BadEmail`, `429 CodeRecent { retryAfter }`, `429 TooManyCodes { retryAfter }`, `429 SignInsBusy { retryAfter }`, `403 SignInsFrozen` |
| POST | `/auth/judge/login/` | public | `{ email, code }` | `{ jwt }` with the judge claims (§0). `403 BadCode { triesLeft }`, `429 CodeLocked { triesLeft: 0 }`, `410 CodeExpired`, `429 SignInsBusy`, `401 Revoked`, `403 SignInsFrozen` (see below) |
| POST | `/auth/judge/link/` | public | `{ token }` | `{ email, expiresAt, name, org, room }`. **Does not consume the token.** `410 LinkExpired` if used or expired, `401 Revoked` for a revoked judge. | POST | `/auth/judge/redeem/` | public | `{ token }` | `{ jwt }`. The limits (`lib/auth/limits.ts`, enforced by the mock exactly) are per email and event-wide, **never per IP** (the whole venue shares one NAT address). The per-email limits are the same for every email whether or not it is on the roster, and a tripped breaker refuses every request alike, so no answer reveals who is a judge.

**`/auth/judge/verify/`**

- It answers `{ success: true }` for any well-formed email, so nobody can use it to check who is on the judge list. Only roster judges (not revoked) get an email.
- **No code is stored for an email that is not on the roster** (S13): nothing was sent. It gets a code-less entry with the same counters (sends, tries, failures), so every limit and every answer below is the same as for a roster email, in a bounded store (at most 5000 entries, oldest dropped, each kept an hour; `NON_ROSTER_ENTRIES_MAX`). adonix: a separate capped (TTL-indexed) collection, never `AuthCode`.
- The code is **6 random digits from a CSPRNG** (no modulo bias); the one-tap link token is **32 random bytes** (base64url, 43 characters), single use, 15 minutes. Both are in one `AuthCode` per email. The emailed link is `https://<gavil>/auth/magic?token=<token>`; a new email makes earlier links stop working.
- A resend while the code still works (unexpired, under 5 wrong tries) **re-sends the same code with the tries already used** (asking again never resets the tries); a new code is drawn only once the old one expired (15 min) or locked.
- Limits: **60 s between sends** (`429 CodeRecent { retryAfter }`), **5 sends per email per hour** (`429 TooManyCodes { retryAfter }`), and a **global breaker** of 120 sends per 10 min event-wide (`429 SignInsBusy`). The breaker counts **emails that actually go out** (roster judges, not revoked): requests for made-up addresses send nothing and never fill it. Once full it refuses every request alike (roster or not).

**`/auth/judge/login/`**

- Only a code `/verify/` sent: none, or expired after **15 minutes**, is `410 CodeExpired` (ask for a new one).
- Each code allows **5 tries** and is then void (`429 CodeLocked { triesLeft: 0 }`); and an email gets at most **10 wrong tries per rolling hour across codes**, so asking for new codes never buys fresh guesses past that (≤ 10 guesses an hour at a 1-in-a-million code).
- A wrong code gets `403 { error: "BadCode", triesLeft }`. An email that is not on the roster fails exactly the same way (it never signs in as anyone).
- A **global breaker**: 300 wrong tries per 10 min event-wide is `429 SignInsBusy` (spread-out guessing across many emails). It counts **wrong tries at a roster judge's code** only: a guess for a made-up email can never sign anyone in (it still uses up that email's own tries), so it doesn't count. Once full it refuses every login alike.

**Global breakers: alerts and the known risk**

- Each breaker that fills writes one AuditLog entry per trip (`actor: "system"`, `action: "signin.breaker"`, `target: "codes" | "logins"`, a reason that points staff to the desk QR). adonix also posts it to the staff channel. A desk QR (`POST /judging/magic-link/`) and judges already signed in are unaffected.
- **Known risk (accepted, recorded in `docs/decisions.md`):** both breakers are unauthenticated and event-wide by design (no per-IP limit behind the venue NAT). Someone who knows enough real judge emails can still trip them, repeatedly: at least 24 roster addresses for the send breaker (5 sends each per hour) or 30 for the login breaker (10 wrong tries each per hour), and each of those judges is locked out of email codes for the hour anyway. Counting only roster sends and roster guesses removes the cheap version (a script with made-up emails). Mitigations if it happens: the desk QR; adonix may add a per-source bucket for requests that do not come from the venue's NAT address range, and a staff alert on every trip.
- The right code for a revoked judge is `401 Revoked` and leaves the code as it was. A successful sign-in uses the code up.

**Freeze new sign-ins** (`EventSettings.signInsFrozen`, admin switch, audited)

- While frozen, `/auth/judge/verify/` and `/auth/judge/login/` answer `403 { error: "SignInsFrozen" }` (an event-wide state, so saying so reveals nothing about the roster; a code try is not used up), and so do `/auth/judge/link/` and `/auth/judge/redeem/` for emailed links.
- A **desk QR** minted by staff (`POST /judging/magic-link/`) still works: staff are there with the judge.
- Judges already signed in keep working. Gav-IL shows "New judge sign-ins are closed. Go to the judging desk…".

**Link and QR redemption is two-step (§7)**

1. `GET https://<gavil>/auth/magic?token=` moves the token into the `gavil_magic` cookie and 303s to `/auth/magic` (S18), which renders "Sign in to judge as <email>?". Gav-IL fills in the email with `POST /auth/judge/link/`, which does not use the token up.
2. **Continue** POSTs to Gav-IL's `/auth/magic/redeem` (the token from the cookie), which calls `POST /auth/judge/redeem/` and verifies the JWT it returns (S8).

**Which refusal wins** (S23, pinned by tests): while sign-ins are frozen, a code login, an emailed link's lookup and its redeem are `403 SignInsFrozen` **before** a revocation is looked at (an event-wide state, nothing used up); a desk QR ignores the freeze but not the revocation (`401 Revoked`, the link stays unused); staff can't mint a desk QR for a revoked judge, frozen or not (`409 Revoked`, nothing minted, nothing audited).

Nothing is ever redeemed on a GET, so email scanners that pre-open links can't burn them. A used or expired link shows "Link expired." with "Send me a new link".

**Desk QR**

- Staff mint one with `POST /judging/magic-link/` (§3). It is the same `/auth/magic?token=` URL, with a 32-random-byte token.
- It is single use, has a **2-minute** expiry, and is bound to that judge's assignment. Minting a new one voids the judge's previous desk QR.

**Gates (every lease)**

- `409 NotCheckedIn` until the judge checks in. `409 RoundNotOpen` before `startsAt` (phase `checkin`/`countdown`).
- After `endsAt`, `next` returns the judge's open visit (so the final evaluation and its comparison still work, within a 15-min grace window), **also when its lease lapsed** while the phone was locked (the revival rules below), and otherwise `status: "time-up"` without writing a lease.
- **Past the grace window** `next` and `progress` say `time-up` even with an unvoted pair (a vote can't count any more), and `compare` is null.

**`GET /judging/next/`**

- An owed comparison comes **first**, before anything else: `status: "compare"` even when the judge holds a live lease (it stays leased, is renewed by the evaluate screen, and is returned after the vote). Otherwise a table leased just before an evaluation that completes a pair (an upgrade of the judge's own skip, an old tab's renew) would move the chain on and the pair would never be voted on.
- Then one atomic `findOneAndUpdate` returns the judge's active `Visit`, or revives a lapsed visit the judge had checked in at (the revival rules below; every such visit is considered, newest first, not only the last one), or picks a project (§4) and writes a new lease: **`phase: "en_route"`, a 4-min TTL (`EN_ROUTE_SECONDS`) and `nudgeAt` at 3 min (`EN_ROUTE_NUDGE_SECONDS`)**, when the phone offers "Can't find it?". A matching arrival switches it to `at_table` with the 10-min lease.
- **The exclusive lease**: at most one active visit per project and one per judge (partial unique indexes on `Visit (eventId, projectId)` and `Visit (eventId, judgeId)` where `status = active`). If the insert loses a race it fails (`409 LeaseTaken`, ask again); it never creates a second lease. `progress` uses the same validity test as `next` (`liveVisit`: active, unexpired, still in the judge's room and path, not held, no conflict), so it never says `evaluate` for a table `next` would take away.
- A live visit whose project is no longer in the judge's room (staff moved them), is held, or is a conflict is ended first (`reassigned` / `expired`).
- `status`:
  - `project`: a table is leased. `prizes` = what this project can be nominated for. `draft` = autosaved notes and nominations.
  - `compare`: a comparison is owed first. **No new lease is written**, so a pending comparison can never be skipped by reloading or pressing Back.
  - `wait`: tables are still owed but none can go now: leased to another judge, cooling down after an absent report, or one this judge just deferred ("team busy" / "can't find") that isn't due back yet. `waitSeconds` = until the soonest frees up. `waiting = { leased, cooling, deferred }` counts which, so the screen says why. Never shown as "Round 1 complete".
  - `done`: nothing is owed to this judge.
  - `time-up`: Round 1 ended and the judge has no open table.

**Two-phase visits**

| Phase | Lease | Renew | Runs out |
|---|---|---|---|
| `en_route` (leased, walking) | 4 min, `nudgeAt` at 3 min | never extended | **released without penalty**: `status: "expired"`, `releasedAt` set, the table goes back to the queue; no skip, no absent report, no view, no deferral, no staff task. The judge simply gets a table again (possibly the same one) |
| `at_table` (code or name matched) | 10 min | extended while the evaluate screen is open | the W1 rules: revived if nobody else was sent; a late submit counts, marked `lateAfterLease` |

- **Evaluations need `at_table`** (`409 NotArrived`), and so do the skips the judge can only see at the table: absent, busy and other (`409 NotArrived`). An absent report also needs **placard proof** (below). "Conflict" ("I know this team") may be said on the way there. "Can't find it" is `defer`, never a skip, and never penalizes the team.
- **Revival** (`canRevive`): a lapsed lease goes back to its judge only if it expired before the end of the grace window and at most 20 min ago; the project is still theirs (room, path, not held, no conflict) and **not cooling down** after someone's absent report; **nobody else was sent to that project since** (an active lease, or any later visit by another judge, even one already finished); and the judge holds no other live lease.
- Arriving on a lapsed en-route visit: counts **only if it can be revived** (a late or backdated arrival never takes a table another judge was sent to); otherwise `409 LeaseEnded` with "No penalty".
- `Visit.wrongCodes` counts the **distinct** wrong codes tried at that visit, each once whatever the `clientId` and whether a scanned token was genuine (S20: neither a replay nor a forged QR games it). Proof that fails at the right table (`422 BadScan`, `422 BadCheck`) is counted apart, in `Visit.proofFailures`. Both are review signals for staff, never a block.

**`POST /judging/visits/:id/arrive/`** (the right-table check, and proof of presence)

The app shows the expected table code before check-in, so typing it proves nothing. The check keeps its purpose (catch honest wrong-table mistakes, by the code) and adds **proof** the judge read the placard:

- Every table has a printed placard with a **room-qualified table code**: the room letter plus the 2-digit local table number (`A12` = Room 4217, table 12), a **2-character check printed only on the placard** ("A12 · K7"), and a QR. Codes are unique across the event and validated before the event (`validateSeed` in `lib/judging.ts`: well formed, a room that exists, inside its table range, used once).
- **Check codes** are stored per TABLE (not project, so moving a team needs no reprint), drawn by adonix with a CSPRNG at seed time from the look-alike-free alphabet `ACDEFHJKMNPRTUVWXY23479` (23 characters, 529 checks; no 0/O, 1/I/L, 5/S, 6/G, 8/B, Q, and no Z: a typed "Z" is read as "2", `CHECK_FOLDS`, so the canonical A14 · W2 is in the alphabet and nothing collides). The demo dataset fixes A12 K7, A17 M3, A20 T9, A22 R4, A14 W2 and draws the rest from a seeded rng (`TABLE_CHECKS` in `fixtures.ts`). A check is **never sent to a judge's phone before arrival**: not in `NextProject`, `RoomPlan`, `JudgeMe` or anything else a judge reads.
- **The QR** encodes `https://judging.hackillinois.org/t/<CODE>?k=<k>`, `k = base64url(HMAC-SHA256(GAVIL_PLACARD_SECRET, eventId|code|check))`, the **full 43-character tag** (256 bits; never cut below 128 bits, S4) (`placardToken`): the **table**, never the project, and no personal data. The secret stays in adonix (the mock uses a fixed dev secret).
- **Residual risk (recorded, S4):** `k` is a printed value. A photo of a placard proves only that someone saw that placard, not that the judge is standing there now; nor does a typed check. What limits it: the token travels no further than the QR's own request (the scan grant below), a proof only ever counts for the judge's own leased table, and the **implausible-proofs** review signal (§3): proofs at two different rooms under 60 s apart (no staff room move between them), or proofs with no time to walk (under 5 s after the walk began). Rotating checks per round (a reprint) is the stronger fix if it is ever abused. **The QR is a weak attestation, and the contract says so (CFX 3).** What would make it strong is a live challenge that a photo can't carry: a code the team's attendee app (or staff) shows and rotates every minute, typed or scanned at the table, checked by adonix; that needs the attendee app and an adonix endpoint and is not built (followup). Until it is, a scan the judge did not make by pointing a camera is at least **recorded as such**: a link opened **signed out** waits in the pending-scan cookie and is posted by the sign-in that follows (up to 10 min later), and the grant minted from it carries `carried`; the arrive action then sends **`carried: true`** (a field only the Gav-IL server sets), adonix keeps it on the arrival (`VisitArrival.carried`), and the Judges tab lists it as the **`carried` visit signal** ("placard scan opened signed out and posted by the sign-in that followed"). It blocks nothing and never flags a judge by itself; staff weigh it with `no-walk` and `rooms-apart`.
- In order:
  1. `409 WrongJudge` if `judgeId` isn't the caller; a replayed `clientId` returns the visit as it is and changes nothing.
  2. The **code part** must be the leased project's table. Another table is `409 WrongTable`, no table `409 UnknownTable`, both with an **`ArrivalProblem`** naming the project there and where theirs is; **no check is asked** for a wrong table (an honest mistake). A malformed code is `400 BadTableCode`. **One exception (S3):** the code of the judge's **last, name-only table** (a visit checked in by the team's name whose evaluation went in at most 10 min ago, `SKIP_UPGRADE_SECONDS`, before the grace window ended; its nominations held, or already released) is checked as **that** visit's proof (steps 3 to 5 for that visit: the QR's `k`, or the check with its per-table misses and lock) and answered `409 EarlierTable` with an **`ArrivalEarlier`** `{ result: "earlier", code, projectName, visitId, released, already?, reason?, triesLeft?, expected, expectedName, message }`: `released: true` when its held nominations count now ("Placard A12 checked: your nominations for NeuralMesh count now. EcoLens is at A17.") or already did (`already`), `released: false` with the refusal that visit would give (`reason`: `BadScan`, `CheckRequired`, `BadCheck`, `CheckLocked`). **This** visit is unchanged (nothing unlocks) and **no wrong code** is counted at it; the answer's `clientId` is not kept (a replay is answered `already`). This is how a judge who checked in by name and then finds the placard can still prove it after Submit, when the phone already shows the next table (or the compare, wait or done screen, through `/judging/arrive/`).
  3. The lease (below): a visit that ended, or a lapsed walk that can't be revived, is `409 LeaseEnded` before any proof is asked. **Exception (S3):** a **name-only visit already submitted** may still get its proof: a scan or typed check at that visit **within 10 min of the Submit** (`SKIP_UPGRADE_SECONDS`, the judge is still at the table; before the grace window ends) is accepted, sets `arrivedBy`, closes the placard task and **releases the evaluation's held nominations** (below). Later it is `409 LeaseEnded`.
  4. **Proof.** `scan` needs that table's `k` (inside the scanned URL in `code`, or as `k`): `422 BadScan` ("That QR didn't check out. Type the 2 characters after the dot on the placard.") for a missing, edited or other table's token. `typed` needs the check, inside `code` ("A12K7", "A12 K7", "A12·K7", any case; "Z" reads as "2") or as `check` (`normalizeCheck`): `422 CheckRequired` without one, or with only one of its two characters ("A12K", "A12 · K": "Type both characters after the dot on the placard.", no miss counted; "A123" is still not a code), `422 BadCheck { triesLeft }` when wrong (no penalty: it is not a wrong code), both with "Type the 2 characters after the dot on the placard."; after **5 wrong checks for that table by that judge, across all their visits to it** (S5: kept per `(judgeId, tableCode)`, never reset by a new lease; `Visit.checkMisses` is the visit's share), typing it is `429 CheckLocked` ("Scan the QR on the placard, or ask the team their name."). A check with a character no check ever has (`checkHint` in `lib/judging.ts`: O, 0, I, 1, L, and S, 5, G, 6, B, 8, Q) is a misreading, not a guess: `422 CheckRequired { triesLeft, lookAlike: true }` with "Checks never use O, 0, I, 1 or L. Look again at the 2 characters after the dot." (or the S/5/G/6/B/8/Q line), and **no miss is counted**. The phone gives the same hint offline.
  5. Time: the server stamps the arrival; a phone `createdAt` is honoured within 2 min, or 20 min for an outbox replay (`queued: true` or `sentAt`), and never before the lease (§0).
- The **first** passing check sets `phase: "at_table"` and `arrivedAt` (sticky). `arrivedBy` is the **first proof** (`scan` or `typed`) and is then sticky; a name check sets it to `name` only until a scan or typed check at the same visit replaces it (`arrivedAt` stays, and the placard task the name check opened is closed with "Then checked in with the placard…"). Every passing check is appended to `Visit.arrivals { method, at, clientId?, queued? }` (the last 10). A wrong code at a visit that already ended (submitted, skipped, deferred) still names the project there but counts nothing. Notes, nominations and Submit are only shown after this. The evaluation records `arrivedBy`. `hasPlacardProof(visit)` (any `scan`/`typed` in the history) is what an absent report and Table talk need.
- The details of `WrongTable` / `UnknownTable` are an **`ArrivalProblem`** `{ result, code, tableCode, projectName, at, reason?, expected, expectedName, expectedRoom, directions, message }` (`checkArrival` in `lib/judging.ts`; the phone builds the same object offline from its RoomPlan):
  - **mismatch**, `409 WrongTable`: a project sits at that code. `at = { projectId, name, tableCode, room }`. "A14 is LedgerLite. NeuralMesh is at A12." / "B12 is in Room 4218 (Vault). NeuralMesh is at A12."
  - **unknown**, `409 UnknownTable`: `reason` `empty-table` ("No project is at A13. …"), `out-of-range` ("There's no table D56. …") or `no-such-room` (a letter no room has).
  - `directions` (`directionsHint`): "Same room: A12 is 2 tables before A14." / "Wrong room: you're in Room 4218. A12 is in Room 4217 (Gold placards, Siebel Center, 4th floor)." / "Room 1404 has tables D01–D32. …" / "Table codes start with A, B, C, D. …".
  - A malformed code is `400 BadTableCode`.
- `method: "name"`: no placard or it won't scan; the judge asks the team its name and taps "Yes, they're NeuralMesh". It is an **attestation, not proof**: it unlocks notes, nominations and Submit, but is **recorded** (`arrivedBy: "name"` on the visit and the evaluation), **flagged for staff** (each name check-in is a visit-level signal on the Judges tab with the time spent at the table; 2+ flag the judge, §3), creates one staff `placard` task for that table (only when it is how the judge first arrived; a replay or a second tap doesn't task staff again), and can **not** file an absent report (`409 NeedsPlacard`: the team confirmed its name, so it was there) or start Table talk (`409 PlacardRequired`, §6). **Its evaluation's nominations are held** (S3): the notes are kept and the evaluation counts for coverage (`views`), but the evaluation is stored with `nominationsPending: true` and its nominations count toward nothing (prize counts, Round 2 finalists) until a scan or typed check lands at that visit (before Submit, or within 10 min after it, also from the next screen: step 2's exception) or staff confirm the placard task (Done, §3). Both stop when nominations close (Round 1 end + the 15 min grace): after that held nominations never count, so Round 2 finalists can't change mid-deliberation. Admin shows them as pending (`StaffTask.pendingNominations`, `PrizeSummary.pendingNominations`); the judge's My notes says so. An edit keeps a held evaluation held. A later scan or typed check at the same visit is proof: the visit (and the evaluation submitted after it) then says `arrivedBy: "scan" | "typed"`, it is no longer a name arrival on the Judges tab, and its placard task is closed. A name check on a visit already matched by code (a stale outbox item, a second tap) changes nothing.
- **Placard QR route** (Gav-IL, `GET /t/<CODE>?k=<k>`): a redirect that **never changes judging state** (no-store, no-referrer, noindex), and the only request that carries `k` (S4):
  - A signed-in judge: `k` is checked (`POST /judging/placards/check/`, read-only) and swapped for a **scan grant**: a signed, httpOnly, `SameSite=Lax` cookie (`gavil_scan`, path `/judge`, **120 s, single use**) bound to the session subject and the table code (`lib/auth/grant.ts`, HMAC-SHA256 with `GAVIL_GRANT_SECRET`). The redirect is `/judge/evaluate?at=<CODE>&via=scan` **with no token**; the evaluate screen runs the check with **one** `POST` through the arrive server action, which reads the grant (method `scan`, no `k` in the body) and sends `POST /judging/visits/:id/arrive/ { method: "scan", code, k, clientId, judgeId }`. The grant is **claimed** (read and spent in one synchronous step) before that call goes out, so two requests racing with one cookie (a double tap, two tabs) never both carry `k`: of the two, one calls adonix and the other **takes that request's answer** (`withScanGrant`, `lib/auth/scan.ts`: it recognises the grant it carries while the first is out, and returns the same result, so a legitimate visit never counts a proof failure for its own double tap). A request that **started before the first finished** gets that answer too, even if it reached its claim after (the order is a counter, not a clock); one that starts after the first has finished is a replay (a copy of the cookie): the grant is spent, it carries no `k` and adonix answers `422 BadScan`. (Two different operations on one grant, `arrive` and the in-app scanner's `arriveAt`, do not share an answer.) The cookie is deleted with adonix's answer; a call that adonix **did not process** gives the grant back for the retry: never reached (offline, a timeout), a 5xx, `408`, a rate-limit `429` (the outbox's own `retry` classification, so a transient `503` no longer costs the judge the scan and a retyped check; adonix dedupes the retry by the grant's `clientId`, so a `504` that did commit is no problem), or was for another judge (`WrongJudge`). Residual: the spent-nonce set is per Gav-IL server isolate, so a copy of the httpOnly cookie replayed on another isolate within its 120 s adds `k` once more there. Both uses carry the **same arrival `clientId`, derived from the grant's nonce** (`grantClientId`, `scan-<nonce>`: never the phone's), so adonix's unique `(eventId, judgeId, clientId)` answers the replay as the same arrival: one grant is one arrival, durably, with no shared state in Gav-IL. It could only prove arrival at the same judge's own leased table anyway. When the phone is on another step (a comparison owed, no tables left, or waiting for a free table), the evaluate page forwards the scan, code only, to that screen (`/judge/compare?at=<CODE>&via=scan`, `/judge/done?…`; the wait screen is the evaluate page itself), which sends it **once** to `POST /judging/arrive/` (the server action adds `k` from the grant) and shows the answer: the placard of the judge's last, name-only table releases its held nominations (`earlier`, S3), anything else is said and changes nothing; it is never kept to post later. A token the API says isn't this table's gets no grant (the POST is then `422 BadScan`); without `GAVIL_GRANT_SECRET` no grant is minted (fails closed: the judge types the check). **adonix keeps accepting `k` in the arrive body** (the mobile app, tests). **Gav-IL's own screens never read or keep a `k`** (S4): a `k` or `token` in the query of a `/judge` or `/admin` request is redirected away by middleware (303, no-store, no-referrer) before the page renders, `scanFromParams` and `arrivalFields` ignore one (a placard URL pasted into the code box keeps only its code), and a scan is never queued, so no placard token is in the address bar, history, RSC payload or `localStorage`. An arrival queued by an older build with its own `k` still replays.
  - Signed out: `{code, k}` waits in a signed, httpOnly pending cookie (`gavil_scan_pending`, 10 min) and `/login?table=<CODE>&next=/t/<CODE>` (**`next` never carries `k`**). After sign-in the browser comes back to `/t/<CODE>` with a full navigation (the code login returns there from the page, not by a server-action redirect, which Next.js would fetch on the server without the browser's cookies; a link or desk-QR redeem 303s there when a scan is waiting), and `/t` reads the pending scan for the same table and grants as above.
  - Staff: `/admin?table=<CODE>`.
  - Link previews and prefetchers never check anyone in, and a wrong scan counts once. The camera's own URL (with `k`) stays in the phone's history: the residual risk above.
- Offline, the phone checks the code against the leased project (it can't check the check or `k`) and queues the arrival (`queued: true`, its `clientId`) before the evaluation; the server checks the proof when it is replayed. A **scan from `/t` is never queued** (S4): the phone never holds its `k`, which waits in the 120 s scan grant, so a replay after that would be `422 BadScan` and the evaluation queued behind it `409 NotArrived`. When its send gets no answer the phone asks for the typed check instead (the code is filled in; the placard is in front of the judge) and queues that; already checked in by name, it says the scan wasn't checked and the name check-in stands. A scan is never queued, with a pasted `k` or without one: the phone holds no placard token. An arrival queued by an older build without `k` is replayed with the grant while it lasts, then refused as above (the check-in step reopens asking for the typed check).

**`POST /judging/visits/:id/defer/`** ("Can't find the table")

- This is **not a skip** and never penalizes the team (no absent report, no cool-down). It sets the visit's `status` to `deferred`, increments `deferCount`, and creates a staff `cant-find` task with the room and table. Only a visit the judge still holds (`status: active`) can be deferred: a lapsed or ended one is `409 LeaseEnded`.
- The project comes back to this judge **first**, once, after their next project. It is **never served straight back**: if nothing else is free, `next` says `wait`, and only after 3 minutes (`DEFER_RETRY_SECONDS`) may the deferred table come back as a retry. A second defer hands it to staff (never served to this judge again).
- The response is the next project.

**`POST /judging/evaluations/`**

- Refused unless all of these hold (in this order): `judgeId` is the caller (`409 WrongJudge`); notes ≤ 20 000 characters (`400 NotesTooLong`); the project is in the judge's room and path (`400 WrongRoom`); it is not held (`409 Held`); it is not a conflict, declared or automatic (`409 Conflict`); every nomination is eligible for that project (`400 IneligibleNomination { prizeIds }`, see §4); the judge has a visit for it that is active or lapsed but theirs, **or** a skip upgrade (below) (`409 NotYourVisit`); and the visit was checked in (`409 NotArrived`). Times as in §0 (`400 BadTime`, `409 RoundOver`; an edit of an earlier evaluation must be made before Round 1 ends).
- **Skip upgrade** (the team came back): the judge's own non-conflict skip may become an evaluation only if it ended their most recent visit to that project, at the table (they had checked in), at most 10 min ago (`SKIP_UPGRADE_SECONDS`), and **nobody else was sent to the project since**. A stale skip never authorises evaluating a table that is now someone else's.
- It ends the visit (`status: done`). Submitting on a lapsed lease is accepted and marked `lateAfterLease` (the judge was there with proof; the queue may already have sent someone else).
- **Table talk fields** (§6) never make an evaluation fail (an offline replay must not dead-letter over a highlight); what can't be kept is dropped and reported in `dropped: { highlights, recording }`:
  - `talkProof = { receipt, segments }` (never stored): the transcript receipt from `POST /api/talk/recordings` and the segments it covers, or a **failure receipt** (the `receipt` in a `502 TranscriptionFailed` / `413 RecordingTooLong` body) with `segments: []`. It counts only when all of these hold, checked in the commit's transaction:
    - genuine (HMAC with `GAVIL_TALK_SECRET`), for this judge and this project, segment hash equal;
    - **fresh on the server's clock**: issued at most 30 min before the server receives the write. The write's honoured `createdAt` never extends it (an outbox replay may backdate a write by 20 min; backdating can only shorten a receipt's life), and a receipt issued after the write's honoured time (beyond 2 min of skew) is refused (the write can't predate its transcript);
    - **for the visit this evaluation is about**: a first evaluation's own visit (or the skip it upgrades, §2 skip upgrade), an edit's the visit the first version ended. A receipt from an earlier visit to the same table (busy, then back) never becomes the later visit's talk;
    - **single use**: unused, or used by this same evaluation `clientId` (a replay). adonix keeps `(eventId, receipt signature) → clientId` once the receipt keeps something; another write can't add from it (identical stored items still need no receipt, below). The receipt is part of the write's content, so the same `clientId` with another receipt is `409 ClientIdReused`;
    - table mode: **re-checked at keep time**, the visit has placard proof (`hasPlacardProof`) and the receipt's consent is inside it (`[arrivedAt − 60 s, issuedAt + 120 s]`).
  - `recording = { mode: "table" | "memo", status: "ready" | "failed" | "too_noisy", consentAt?, durationSec }` is new only with a receipt that counts (above), when the event switch is on and (table mode) the team didn't opt out. Its `mode`, `consentAt` and `durationSec` are **the receipt's**, never the phone's. A failure receipt stores `status: "failed"` (whatever the phone said) and backs nothing else; a transcript receipt stores `ready` or `too_noisy`. **No receipt, no recording metadata**: a phone-made `failed` (memo or table, with its own `consentAt`) is dropped (`dropped.recording`). An upload that never reached the server leaves no trace (the phone keeps it queued, §6).
  - `highlights: KeptHighlight[]` (`{ kind, text, quote?, t?, certainty, state: "kept" | "edited", demoStatus?, concernKind? }`): a new item needs a verified `talkProof` and must pass `validateKept` against its segments (known kind, text ≤ 200 chars and never a score, rank, verdict, instruction or self-advocacy; a quote ≤ 25 words that is a word-for-word run of the transcript and touches no steering segment; `t` is the matched segment's time, a client `t` is ignored; a presenter needs a quote; `demoStatus` only on a demo item and `concernKind` only on a concern; a demo status with no quote is stored as `unclear`, it has no evidence); the server sets each item's `mode` (`table` | `memo`) from the receipt; at most 12 in all.
  - **An edit keeps what is already stored** (the receipt lasts 30 min, edits are allowed until Round 1 ends, and the audio is gone):
    - No `recording` keeps the stored recordings. A verified one replaces only the stored recording **of its mode**: a memo added by an edit sits **beside** the table recording (the evaluation's `recording` stays the table's, with its `consentAt`; the memo is `memo`). On its own a memo is `recording`. A recording that can't be verified (no receipt, a stale one) keeps the stored one of that mode, and a failed upload's metadata never replaces a transcribed one.
    - No `highlights` keeps the stored items (a notes-only edit). A list (even `[]`) is what the judge keeps for the recording the write is about (the receipt's mode, else `recording.mode`; with neither, for the whole evaluation): an item is kept when it passes the check above against this write's live receipt, **or is identical to a stored item** (kind, text, quote, certainty, state, demoStatus, concernKind; it was checked when it was stored, so re-sending or removing items needs no receipt, even after its 30 min). A new or reworded item without a live receipt is dropped and counted. Stored items of the other recording stay.
    - `dropped.recording` is true when the sent `recording`'s mode has no recording after the write; `dropped.highlights` counts the sent items not kept. Switching Table talk off, or a team opting out later, never erases what was stored.
  - `demoStatus` (`ran_live | partly_ran | did_not_run | not_shown | unclear`) is the judge's own tap and is kept regardless.
  - Highlights never nominate: `nominations` only ever come from the judge's own list.
  - `/judging/compare/` and `/judging/notes/` return the kept `highlights`, `demoStatus`, `recording { mode, status }` and `memo { mode, status }` (a memo beside a table recording) with each judged project (the compare recall block shows only kept items).
- The first evaluation of a project by this judge increments `views` (an evaluation after the judge's own absent skip is an upgrade and counts once). It records `dwellSeconds`, the time at the table. For a submit sent straight away (its honoured time within `CLOCK_SKEW_SECONDS` of the server's clock, `sentAt` or not) that is the server's own clock alone: from when it **received** the first arrival check (`Visit.arrivalSeenAt`) to when it received this submit. The phone was online at Submit, so a check-in claimed as made offline (`queued`, up to 20 min) or stamped up to 2 min early can't stretch a 30-second visit. The phone's account (honoured arrival to honoured submit) is kept as `phoneDwellSeconds` only when it is longer, for staff to read beside it. An outbox submit (made over 2 min before it arrived) is measured on the honoured times (no `phoneDwellSeconds`), so a visit made offline end to end is never "fast" by its replay. What stays possible is a phone that claims both the check-in and the Submit were made offline: it is believed only inside the §0 bounds (20 min old at most, after the lease, inside the grace window), and staff can see such a visit (`Visit.arrivals[].queued`, the evaluation's `createdAt` against `submittedAt`). The fast-judging signals (§3) read `dwellSeconds`; under 75 s is a review signal, never a block. An edit keeps the first version's measures (`dwellOf` in the mock).
- It is idempotent per `clientId` (`409 ClientIdReused` for the same id with other notes or nominations). Resubmitting with a new `clientId` edits the evaluation (no new view).
- `next` is `"compare" | "evaluate" | "wait" | "done"`: `compare` when the judge's last two evaluated projects in this room are unvoted; otherwise from `/progress/`.

**`POST /judging/skips/`**

- `reason` is `"absent" | "busy" | "conflict" | "other"`, and a note is required for `other`. `409 WrongJudge` for another judge's `judgeId`.
- **A skip never replaces an evaluation**: skipping a project this judge already evaluated is `409 AlreadyEvaluated`. A skip needs the judge's own visit (`409 NotYourVisit`).
- **The table first**: absent, busy and other need the judge at the table (`409 NotArrived`); `conflict` may be said en route. **Absent also needs placard proof** (a scan or the typed check, at any time during the visit): after a team-name check it is `409 NeedsPlacard`. An absent report must be made before Round 1 ends (`409 RoundOver`).
- **An absent report on a lapsed visit** (the at-table lease ran out) counts when it was made (its honoured time) by the time the lease ended: what the judge saw while the table was theirs, even if the outbox sends it later. Made after that, it counts only while the table could still have gone back to them, like a late arrival: **nobody else has been sent there since** and at most `MAX_OFFLINE_SECONDS` (20 min) after the lease ended. Otherwise `409 LeaseEnded` ("Another judge was sent to NeuralMesh after your time there ran out, so this report wasn't filed. No penalty…", or "…ran out too long ago…"), nothing is filed or cooled, and the visit stays as it was. So a judge whose time ran out can't cool, or with an earlier report auto-hold, a table another judge is at with the team (`staleAbsentReport` in the mock).
- What each reason does:
  - `absent`: the visit ends (`skipped`) and the table **cools down for 10 minutes** for every judge. Two reports from **different judges at least 5 minutes apart** auto-hold the project (`absent: true`, out of the queue) and create a staff `absent` task. Admin "Mark present" ends the hold; the judges who found the table empty may then be sent back.
  - `busy`: the team is presenting to someone else. **No penalty**: the visit is `deferred` (no staff ping, no view change, not in My notes) and the project comes back to the same judge **first, after one other table**. It never comes straight back: with nothing else free the judge waits (3 min, or until another table frees up). After a second busy report it is a normal candidate again.
  - `conflict`: the project is added to `conflicts` and never shown to this judge again.
  - `other`: the note goes to staff as a `skip-note` task.

**`GET /judging/compare/`**

- **Original Gavel:** `b` is the project just evaluated ("Just now") and `a` is the judge's previous non-skipped project ("Earlier"), both in the judge's current room.
- It returns null if the judge has fewer than 2 evaluated projects since their last room move, or already voted on this pair. A room move restarts the chain.
- There is no opponent picking.

**`POST /judging/votes/`**

- No ties, no self-votes (`400 SamePair`). `409 WrongJudge` for another judge's `judgeId`. `createdAt` is required; it is honoured within the write-time bounds (§0) and then must not be before the two evaluations it compares (`400 BadTime`); past the grace window it is `409 RoundOver`.
- **One vote per pair per judge**: a second vote on the same pair, with any `clientId`, returns the first vote (200). The phone also uses the pair as the `clientId` (`vote:<a>:<b>`), so a re-vote collides.
- Otherwise the pair must be the `/compare/` pair (`400 BadPair`).
- The vote is sent only after the on-phone undo window closes, and commits immediately. The phone shows no Undo once it is sent.

**Round 2 (`/judging/round2/:prizeId/`)**

- Only the judge's assigned prize, and one they may deliberate (`canDeliberate`: company prizes by that company's judges, never MLH) (`403 NotYourPrize`). `409 WrongJudge` for another judge's `judgeId`.
- Until nominations close (Round 1's end + the 15-min grace: `opensAt`), `open: false` and `nominees: []` (finalists aren't final yet, S3: a late evaluation, a proof or staff's Placard OK can still add one); PUT is `409 RoundNotOpen`. **The finalists are decided once, when Round 2 opens, and are final** (CFX 4: adonix takes the snapshot at `opensAt` and persists it; the mock's `freezeRound2` runs before **every** call of the API after it — judge, admin, table check-in, sign-in — because the whole API object is wrapped (`frozenAtOpening`), so even a check-in that clears a hold cannot move the set; adonix: no call may read or change the finalists before the snapshot exists). Nothing after the opening moves the set: not a flag cleared or escalated, not a judge's votes or evaluations voided, not a release of held nominations. Counts shown on the board are the ones it opened with. The explicit policy for a **later disqualification**: a finalist whose project staff hold after the opening (a flag escalated, an absent hold) stays on the board with **`withdrawn: true`**: it can't win, the judge's phone does not offer it for ranking, and a judge's ranking may list it or leave it out (both are valid), so a ranking saved before the withdrawal still resubmits. **Staff's combined ranking enforces it** (CFX 4b): `GET /judging/admin/deliberations/` always lists a withdrawn finalist after every finalist still in (an order saved before the withdrawal included), the editable board shows who was pulled ("Pulled after Round 2 opened: can't win") and offers no move across that border, and `PUT` an order that ranks one above a finalist still in is `400 WithdrawnAbove` (`details.withdrawn`: the pulled project ids). Nothing is ever added after the opening (a hold cleared later does not make a finalist; staff would have to add one by hand, which this contract has no call for). Before `opensAt` the staff view (`GET /judging/admin/deliberations/`) is a live preview of the set that will be frozen.
- **Timing like every write**: deliberation closes at `RoundState.deliberationEndsAt` (phase `closed` after it; the mock sets it 60 min after Round 1 ends unless told otherwise, `deliberationMinutes: 0` leaves it open). The close is judged on the ranking's honoured time, never on when it arrives. A ranking's `createdAt` (sentAt-corrected) is honoured within 2 min, or 20 min for a replay: a ranking made before the close still counts when it arrives after; one made after is `409 RoundOver`; one that claims to predate Round 2 is `400 BadTime`. `submittedAt` is the honoured time.
- Finalists: HackIllinois prizes take the top N most-nominated (N per prize in Settings, default 8); company and MLH prizes take every project that opted in on Devpost; Pro / General overall take the top 3 per room of that path by Round 1 ranking. Held projects never go through.
- Each nominee carries **`devpostUrl`** (the project's Devpost page, `Project.devpostUrl`): the board's "Demo" link opens it in a new tab so a judge in Room 2405 can watch every demo before ranking. Only an http(s) address is ever linked (`webUrl`); a nominee with none has no link.
- A finalist the judge has a conflict with (declared, or a team member at the judge's company) is returned with `recused: true`: shown, not rankable. The company-track rule does not apply in Round 2 (company prizes are decided by that company's judges).
- The judge's PUT `order` must name every non-recused, non-withdrawn finalist exactly once, and may also name a withdrawn one (`400 BadOrder` otherwise). Staff's PUT (`/judging/admin/deliberations/:prizeId/`) must name **every** finalist once, the withdrawn ones after all the others (`400 BadOrder` / `400 WithdrawnAbove`).

### Data written (design doc §8)

Every collection is scoped by `eventId`. Unique indexes:

- `Evaluation (eventId, judgeId, projectId)`
- `(eventId, judgeId, clientId)` on every write collection (arrivals included); `(eventId, userId, clientId)` on team check-ins
- `Visit (eventId, projectId) where status = active` and `Visit (eventId, judgeId) where status = active`. This is what makes the lease exclusive: one judge per table, one table per judge.

Fields added in H-integ:

- `TableCheck (eventId, tableCode) → check` (2 characters, CSPRNG at seed time; staff-only, printed on placards). `GAVIL_PLACARD_SECRET` signs QR tokens.
- HF-integ: `Evaluation.nominationsPending` / `nominationsReleasedBy` (`scan | typed | staff`), `StaffTask.pendingNominations` (prize names), `PrizeSummary.pendingNominations` (S3), `StaffTask.nominationsClosed` / `PrizeSummary.nominationsClosed` (held nominations can no longer be released); `Visit.proofFailures` (S20); wrong placard checks per `(eventId, judgeId, tableCode)` (S5); arrival replays keyed by `(eventId, judgeId, clientId)` with their visit and content (S22); non-roster sign-in limits without a code, capped and TTL'd (S13). After its verifier: `409 EarlierTable` / `ArrivalScan` `earlier` with an `ArrivalEarlier` (the last, name-only table's placard after Submit, §2 step 2); the implausible-proofs signal leaves out pairs around a staff room move and measures a re-leased walk from its first lease; the admin task list shows `teamCheckedInAt`.
- `Visit.arrivals[] { method, at, clientId?, queued? }`, `checkMisses`; `arrivedAt` is sticky (the first passing check), `arrivedBy` is the first proof (`name` until one arrives); `arrivalSeenAt` (server receive time of that first check). `Evaluation.dwellSeconds` and `phoneDwellSeconds` (§2).

**Fast-judging signals (`AdminJudge.speed`, review only, never a block)**

`SpeedSignal { evaluations, fastVisits, medianDwellSeconds, nameArrivals, votes, votesPerHour, roomMedianVotesPerHour, medianScope, visits, flags }` (`speedSignals` in `lib/floor.ts`). Judge-level flags need a pattern, never one visit:

- `fast-visits`: **2 or more** evaluations under **75 s** at the table, or a median under 75 s over **3 or more**. Time at the table is `Evaluation.dwellSeconds` (§2): the server's clock, from receiving the check-in to receiving the submit, when the submit was sent straight away, so a check-in replayed from the outbox, or stamped early inside the clock allowance, can't stretch a 30-second visit. One very short visit is not a judge flag: it is listed in `visits` (a visit-level signal).
- `vote-rate`: at least 4 counted votes and a rate over **2× the peers' median**, or over 30 an hour whatever the peers do. **Peers never include the judge**: the other judges in the room who have voted, or, when the room has **fewer than 3 judges** (every canonical room has 2), every other judge on the **same path** who has voted (`medianScope: "room" | "path"`; `roomMedianVotesPerHour` is that median, `null` with no peer voting). Rates count from the judge's first lease, over at least 15 min.
- `name-arrivals`: **2 or more** tables checked in by the team's name instead of the placard, **whatever the visit ended in**: evaluated, skipped (busy, other, conflict), still open or lapsed. One table checked in by name twice counts once.
- `implausible-proofs` (S4: a photo of a placard proves only that someone saw it): placard proofs (scan or typed check, by the server's receive time `Visit.arrivals[].at`) in **two different rooms under 60 s apart** (`ROOMS_APART_SECONDS`; once flags the judge) **with no staff room move between them** (a move, `AuditEntry` `assign` for that judge, between the two proofs means they were sent there: `SpeedInput.roomMoves`), or **2 or more** visits whose first check was a proof **under 5 s after the walk began** (`NO_WALK_SECONDS`: no time to walk). The walk begins at the visit's lease, except for a table leased again right after its en-route lease ran out (the judge's visit just before it was to the same table, released without arriving): then at the first of those leases, so a slow walk is never "no walk". Outbox replays (`queued`) are left out: their receive times say nothing about walking. Each case is also a visit-level signal (`rooms-apart` with `gapSeconds` and `otherRoom`, `no-walk` with `gapSeconds`).
- `visits: VisitSignal[] { projectId, tableCode, projectName, signal: "fast" | "name" | "rooms-apart" | "no-walk" | "carried", dwellSeconds, phoneDwellSeconds?, arrivedBy?, outcome?, gapSeconds?, otherRoom? }`: every fast evaluation, every name check-in, every implausible proof and every `carried` placard scan (opened signed out, posted by the sign-in that followed: a weak proof of presence, CFX 3), so staff see the single cases too (the Judges tab lists them, `signalLines` in `lib/floor.ts`). `outcome` is `evaluated | skipped | open | ended`; `dwellSeconds` is the time at the table: arrival to submit (the server's measure for a submit sent straight away), to the skip, to now (open), or to when the lease ended. `phoneDwellSeconds` is the phone's longer claim when it differs from the server's ("30 s by the server's clock; the phone says 3 min 30 s": its check-in reached the server later than it says it was made). Only an evaluation can be `fast` (a quick busy skip is not fast judging).

**`POST /judging/admin/judges/:id/revoke/`**

- It sets `JudgeAssignment.revokedAt` and ends the judge's active visits (`revoked`).
- `voidVotes: true` also excludes the judge's votes from every ranking (replayed without them; the votes stay stored for the audit trail) and removes their evaluations from `views` and nomination counts.
- **Only a verified identity names the judge whose data `/login` clears** (CFX 10): `gavil_clear` is set from `verifiedClaims` (`lib/auth/verify.ts`): a token whose HS256 signature checks out (the mock secret, or the shared `GAVIL_JWT_SECRET`), expired or not, or adonix's own `401 Revoked` (adonix has checked the signature itself to know who is revoked). A cookie that merely decodes (a forged one with JUDGE claims and a past or missing `exp`, e.g. planted from a sibling subdomain) is signed out and names nobody; with no shared secret an *expired* session names nobody either (only adonix could say, and it will not answer for an expired token). Sign-out (`POST /auth/logout`) also expires adonix's own `jwt` cookie in the browser, host-only and on the shared domain (`Domain=hackillinois.org`, raw `Set-Cookie`): `auth.logout()` is a server to server call whose `Set-Cookie` never reaches the browser, and a staff member who signed in with Google on a shared laptop would otherwise leave a valid bearer token for the adonix API behind; a GET that lands on `/auth/logout` (a 401, a pasted link) does not touch it.
- It takes effect on the judge's next call (§0). A 401 inside a judge server action that carries nothing to lose (the check-in button, the help request) is handled **by the action itself**: it deletes the session cookie, sets a 2-minute `gavil_clear=<eventId>:<judgeId>` cookie for a judge session, and goes to `/login?error=revoked|expired` (a redirect from a server action is a client-side navigation, so a route handler's `Set-Cookie` on it may never reach the browser). A 401 inside a **write** (or a poll or renewal that fires while the judge types) is answered as data and touches no cookie (§3, CFX 2: the screen keeps the write on the phone first). Elsewhere a 401 goes through `GET /auth/logout?next=<page>&error=expired`, which signs out **only a session that is really dead** (expired, or adonix answers 401 and says which; the `error=expired` it was given only picks the message when the dead cookie is already gone); a link or QR to it never signs a working judge out, and `next` is a local path with no bearer value (`safeNext`). Either way the cookie is cleared, `gavil_clear` is set, and `/login` then deletes that judge's drafts and sent-vote memory from the phone (`clearPhone`; an **expired** session keeps the notes typed but not yet sent and the sent-vote memory, `keepDrafts`, like it keeps the queue). Their unsent work (queue and refused items) is never deleted unasked, after an expiry or a revocation alike: it stays on the phone and replays when they sign in there again (a revoked judge can't unless reinstated; it is never replayed as anyone else). Only the judge's own explicit choice deletes it (`clearPhone(scope, { dropUnsent: true })`: "Delete them and sign out" after its own confirm, or a sign-out with nothing unsent). Another judge's unsent work on a shared phone is never touched: there is no `Clear-Site-Data`.

## 4. Queue and algorithm (design doc §9)

The reference implementation is `lib/queue.ts` and `lib/gavel.ts`, unit-tested in `lib/__tests__/`.

**Choosing the next project for a judge** (`GET /judging/next/`, one atomic operation that also writes the Visit lease):

1. **Owed** projects are in the judge's room and path and are:
   - not held (a `hold` flag, an escalation, or an absent auto-hold),
   - not a conflict: declared by the judge, a team member whose email is at the judge's company domain, or (Round 1, sponsor judges) a project in the judge's own company track,
   - not already evaluated or skipped for good by this judge,
   - not handed to staff after two "can't find"s.
   **Available** = owed, not leased to another judge right now, and not cooling down after an absent report. Owed but nothing available = **wait**; nothing owed = **done**.
2. **Coverage first.** The fewest completed views wins, so every project reaches 2 views before any project gets a 3rd.
3. **Once every candidate has 2 or more views, use Gavel's rule.** Pick the candidate whose comparison with this judge's **previous** project has the highest expected information gain, with ε = 0.25 random exploration.
4. **Presence.** Teams that checked in at their table (and weren't reported absent since) go first among equals: in the coverage tier, among candidates with the same view count; in the Gavel tier only as a **near-tie-break**, among candidates whose expected information gain is within `PRESENCE_TIE_GAIN` (0.02 nats) of the best (ε-exploration ignores presence). A preference only: coverage-first always holds, a clearly more informative table always wins, and teams that never check in are never starved of judges.
5. **Ties** go to the table nearest the judge's last table, then are broken at random.
6. **Visit lease.** En route it lasts 4 minutes (released without penalty when it runs out); at the table 10 minutes, renewed while the evaluate screen is open. Submit or skip ends it; an expired lease frees the project.
7. **"Can't find the table"** and **"team busy"** defer the visit. The project comes back to the same judge **first**, once, after their next project, and **never straight back**: if it is the only thing this judge could do, they wait (for another table to free up, or 3 minutes, after which it may come back as a retry). A second "can't find" hands it to staff; a second "busy" makes it a normal candidate.
8. **Nothing owed** means Round 1 is complete for that judge; **owed but all leased, cooling or just deferred** means wait.

**Comparison** is always the project just evaluated against the judge's previous non-skipped project in the same room.

**Prize eligibility.** A project can be nominated for a nominatable prize of its path when the prize is a HackIllinois prize, or the team opted into it on Devpost (company and MLH prizes). The overall prizes are Round 2 only. Company prizes are deliberated by that company's judges; MLH prizes are decided outside Gav-IL.

**Beliefs.** Each project has a Gaussian (μ, σ²), updated per committed vote by `updateItems`: a Thurstone/probit Laplace step with a σ² floor of 0.05.

- **μ is only comparable within a room.** Rank with `roomRanking(room, …)`, which ignores any cross-room vote.
- Never rank projects from different rooms against each other.
- μ and σ² are never shown to judges.
- Voided votes (and every vote of a revoked-and-voided judge) are excluded.

## 6. Table talk (consented recordings, private memos, highlights)

The approved design: a judge records the table conversation **only after the team agrees** (a spoken consent script and the judge's tap), no audio is stored, nobody's voice is identified, and the feature is **off per event until counsel signs off**. If the team declines, the judge may dictate a **private memo of their own voice after leaving the table**. Highlights only describe (never score or rank); a prize suggestion needs a verbatim quote and the judge's own tap to become a nomination.

| Piece | Who | Endpoint |
|---|---|---|
| Permission and project facts (read-only) | adonix | `POST /judging/talk/:projectId/context/` (§2) |
| Spending one vendor call (a transcription, a Claude call), atomic | adonix, called **only by the Gav-IL server** (signed) | `POST /judging/talk/:projectId/spend/` (§2) |
| Speech to text | Gav-IL server (route handler) | `POST /api/talk/recordings` |
| Highlights | Gav-IL server (route handler, or the `talkHighlights` server action) | `POST /api/talk/highlights` |
| Kept highlights | adonix | `POST /judging/evaluations/` (`recording`, `highlights`, `talkProof`, §2) |
| Event switch, Claude switch (with the vendor-retention ack), event Claude and transcription budgets, team opt-out | adonix (ADMIN) | `PUT /judging/admin/settings/`, `PUT /judging/admin/projects/:id/recording/` (§3) |

All limits live in `lib/talk/policy.ts` (the numbers below come from it).

**Transcript receipts.** Every transcript the Gav-IL server returns is signed: `receipt = "v1." + base64url(claims) + "." + base64url(HMAC-SHA256(GAVIL_TALK_SECRET, judgeId|projectId|visitId|mode|consentAt|sha256(canonical segments)|durationSec|issuedAt))`, canonical segments = `JSON.stringify(segments.map(s => [s.id, s.t, s.text, s.confidence ?? null]))`, TTL 30 min (`lib/talk/receipt.ts`, Web Crypto only). Highlights (table **and** memo) need the receipt with the very same segments, and an evaluation's kept highlights carry it in `talkProof`, so a judge can't present "the team said X" for a transcript the server never produced, or edit a real one. `GAVIL_TALK_SECRET` (≥ 32 chars) is shared by the Gav-IL server and adonix and **must be set in every deployment's environment** (it belongs next to `CF_*` and `ANTHROPIC_API_KEY`); mock mode (`mockEnabled` in `lib/env.ts`: `GAVIL_MOCK=1` under `next dev` or vitest only, never a deployed build) uses a fixed dev secret; without one every recording and highlights call is `503 TalkNotConfigured` (fails closed), and the server logs once which variable is missing (never a value). **Failure receipts**: when a valid upload (every talk-context check passed, the audio accepted, one transcription spent) can't be transcribed (`502 TranscriptionFailed`, `413 RecordingTooLong`), the error body carries `receipt` and `receiptExpiresAt`: the same HMAC over no segments with `|failed` appended to the MAC input (claims `failed: true`, `durationSec` the server's or 0). It is the **only** way an evaluation stores `recording.status: "failed"` (§2), and it backs no highlights (`403 BadReceipt` on the highlights endpoint). **When an evaluation keeps a receipt** (§2): fresh on the server's clock (never the write's honoured time), for the visit the evaluation is about, not newer than the write, table mode re-checked for placard proof and consent, and single use per evaluation `clientId` (`receiptKey` = its signature). **Both parts of a receipt (and of a spend proof) must be canonical base64url** (unpadded, the one encoding of their bytes: `toB64url(fromB64url(s)) === s`), or it is `BadReceipt` and has no key: `atob` ignores the unused low bits of the last character, so the same HMAC re-encoded ("…wVw" → "…wVx") would otherwise verify under a new key and look unused.

The two Gav-IL handlers are thin wrappers over `lib/talk/service.ts`; adonix (or a Queue consumer, not `ctx.waitUntil`, which stops 30 s after the response) can host the same code instead. Either way the libraries are the reference.

**Talk context (adonix)**

Body `{ mode, purpose: "transcribe" | "highlights", consentAt?, visitId?, queued? }`. **Read-only: it never counts anything**, so a judge calling it with their own session (the JWT is theirs) can't use up their quota or the event's budgets; any other purpose (`stt` and `llm` counted here before) is `400 BadTalkRequest`. Checked **in this order**, so a judge who isn't at a table can't learn whether its team opted out:

1. `403 RecordingOff` while `EventSettings.recordingEnabled` is false (the default). Every recording and highlights call goes through this first.
2. `409 RoundClosed` outside Round 1 judging (after the end plus the 15-min grace window).
3. The visit:
   - `transcribe`, `mode: "table"`: the visit the judge is **sitting at** for this project: the active `at_table` visit, or **a hold that lapsed at the table** with no Submit, no skip and no other table since (the same "still seated" rule as memos below: a judge who asked for consent a few minutes in and recorded a full demo uploads after the 10-min hold; the phone doesn't have to renew it). `409 NotArrived` otherwise (e.g. still en route, or "You've left A17…" after leaving). **A queued upload** (`queued: true`: the recording was made at the table but its upload failed, e.g. venue Wi-Fi, and the phone kept it in its queue) is accepted for the visit it was made at **up to 15 min after leaving that table** (`QUEUED_UPLOAD_SECONDS`; left = submitted, skipped, or a lapsed hold followed by Submit, a skip or another table; `409 UploadWindowClosed` after), with its consent inside that visit (`[arrivedAt − 60 s, left]`, below). Quotas apply as usual. A memo is still refused while seated at another table; a queued table upload isn't (no mic is open).
   - `transcribe`, `mode: "memo"`: never while the judge is sitting at **any** table (`409 StillAtTable`: at this one "Memo after you leave the table"; at another, "You're at A20 now. Dictate memos between tables, not at one.": the mic would pick up a team that never said yes, or one that opted out). En route between tables is fine. **A hold that lapsed at the table still counts as sitting there** until the judge submits or skips it (a late Submit is still accepted, `lateAfterLease`) or is sent to a different table (`409 StillAtTable`, "Memo after you leave the table: submit or skip it first"): a locked phone or a long demo isn't leaving. The visit they left (submitted, skipped, or lapsed and then left that way) **within 15 min** of leaving (a lapsed one: from the Submit, the skip or the next lease) (`409 MemoWindowClosed`), else `409 NotArrived`.
   - `highlights`: `visitId` from the receipt must be one of this judge's visits to this project that reached the table (`409 NotArrived`).
4. `403 OptedOut` for `mode: "table"` when the team opted out. `mode: "memo"` (the judge's own voice, after leaving) is allowed for it.
5. Table uploads only: `409 PlacardRequired` when the visit was reached by team name only (no scan or typed check at that visit, `hasPlacardProof` in `lib/judging.ts`: a name check followed by a scan is proof, the same rule as an absent report); `400 ConsentRequired` without a parseable `consentAt`; `409 ConsentOutOfRange` unless `visit.arrivedAt − 60 s ≤ consentAt ≤ now + 120 s` (server clock; a queued upload: also `≤` the time the judge left the table). The accepted time comes back as `consentAt` (one consent per recording; the receipt carries it).
6. Transcriptions: `TALK_STT_QUOTA` = 2 per judge × project (one and a retry; **a memo shares them**), `429 TranscriptionQuota` when none are left; then the event's `sttBudget` (`TALK_STT_EVENT_BUDGET` = 1500 by default, admin-set 0–20,000), `429 TranscriptionBudget` at the cap. Both checked for `transcribe` (before any audio is read), both counted only by the spend. `transcriptionsLeft` says how many remain for this judge.
7. Claude: `llm` = `highlightsLlm` is on, this judge has quota left for this table (`TALK_LLM_QUOTA` = 3) and the event has budget left (`llmBudget.used < llmBudget.cap`). `llmBlocked: "off" | "quota" | "budget"` says why not. A hint: only the spend counts a call.

**Spend (adonix; the Gav-IL server only)**

`POST /judging/talk/:projectId/spend/ { kind: "stt" | "llm", mode, visitId, consentAt?, queued?, proof }`, sent by the Gav-IL server **right before each vendor call** (the speech-to-text call; the Claude call after the too-short and no-key checks):

- `proof = "s1." + base64url(claims) + "." + base64url(HMAC-SHA256(GAVIL_TALK_SECRET, "spend|" + judgeId|projectId|kind|mode|visitId|nonce|issuedAt|attemptId))` (`lib/talk/receipt.ts` `signSpend` / `verifySpend`), with a random 128-bit `nonce`. adonix refuses (`403 BadSpendProof`, nothing counted) a missing, forged or tampered proof, one for another judge (the JWT's), project, kind, mode or visit, one issued over 60 s ago (`SPEND_TTL_SECONDS`) or in the future, and a nonce already used (kept until it expires). A judge never holds the secret, so a judge can't spend.
- **Attempt ids: a lost answer never costs a second slot (CFX 6).** The claims carry `attemptId`, one per *intended* spend, **stable across its retries** (the nonce is new on every signature). The Gav-IL server makes one per spend (or uses the phone's `attemptId` from the recording's form or the highlights request, so the phone's own retry is the same spend) and, when the answer to a spend never arrives (a timeout, a dropped connection: anything but an answer from adonix), **asks again** (`SPEND_ASKS` = 2) with a new nonce and the same `attemptId`. adonix keeps `(judgeId, projectId, kind, mode, visitId, attemptId)` for `SPEND_ATTEMPT_SECONDS` = 15 min with the original `TalkSpend`; a request for an attempt it has already counted is answered with that result (`replayed: true`) and **counts nothing**, up to `SPEND_REPLAYS_MAX` = 2 times while the attempt is unsettled (then `429 TranscriptionQuota` for `stt`, `granted: false, llmBlocked: "quota"` for `llm`). **A counted slot buys exactly one vendor call (CFX 6b):** once the vendor call has run (the transcription, or Claude, answered or failed), the Gav-IL server sends a **settle** (`POST …/spend/` with `settle: true` and a fresh proof of the same attempt: it counts nothing, marks the attempt consumed and answers the original result with `replayed: true`; `404 UnknownAttempt` when adonix never counted that attempt or has forgotten it). A consumed attempt is never answered again: the replay is refused like a used-up quota, so the phone's retry of a recording whose vendor call already ran gets `429 TranscriptionQuota` ("Record it again, or type notes"; a new recording is a new attempt id). Before the settle the replays are the lost-answer case only (the first ask never reached the vendor), so they are free. Settling is best effort: if the settle itself is lost, `SPEND_REPLAYS_MAX` still bounds the free replays (1 + 2 vendor calls for one slot in the worst case, and only when a settle is lost). A **refusal** (`granted: false`, a 429) is not an attempt and is not remembered. A proof (nonce) is still single use: the same proof twice is `403 BadSpendProof`, and `attemptId` is inside the HMAC, so it can't be swapped after signing.
- Then, **in one atomic step** (a transaction, or `findOneAndUpdate` with the conditions in the filter): every talk-context check again (`kind: "stt"` as `transcribe` with `consentAt` / `queued`, `kind: "llm"` as `highlights` with the receipt's `visitId`); the visit must be the one the proof names (`409 VisitChanged`: the judge moved on between the context and the spend); then the count. `stt`: this judge's transcription for the project **and** one of the event's `sttBudget`, or `429 TranscriptionQuota` / `TranscriptionBudget`. `llm`: this table's Claude call **and** one of the event's `llmBudget`, or `granted: false` with `llmBlocked` (nothing counted). Two requests racing for the last call: exactly one is granted.
- Returns `TalkSpend` = the `TalkContext` it was checked against (its `visitId` and `consentAt` go into the receipt) `+ { kind, granted }`.


Returned facts: `judgeId` and `visitId` (the receipt is bound to them); `prizes` = the project's eligible HackIllinois prizes with `aiSuggest` (Best UI/UX, Most Creative, Best Social Impact, and Most Useless for General), **never Most Popular**, never company or MLH prizes; `vocabulary` = the Devpost name, tracks and tech terms from the tagline and description (Whisper's initial prompt), **never a person's name** and nothing from any other project.

**Consent (phone; UI in the next stage)**

1. "Ask and record" opens a sheet (role=dialog) with the script to read aloud (`CONSENT_SCRIPT` in `lib/talk/policy.ts`), which names who processes the recording and everything Anthropic gets (the transcript of what's said, the judge's own notes, and from Devpost the project's details and the team's first names, never full names; it never says that is all, since a full name said aloud is in the transcript): "Okay if my phone takes notes while you demo? Cloudflare transcribes what's said and Anthropic summarizes it with my own notes; from Devpost it gets your project details and first names, not full names. The audio isn't kept, and only I see the notes. You can say no, and it won't affect judging." Buttons: "They said yes · Start" and "They said no". The participant notice (`TEAM_NOTICE`) names the same processors.
2. Yes: the mic opens and `consentAt` is the tap time; the first seconds capture the spoken yes. "Recording" with a timer is always visible; the team can ask to stop and discard.
3. No: nothing is sent and nothing is stored (a decline is never recorded anywhere). After leaving the table the judge may tap "Dictate a memo" (`mode: "memo"`).
4. The phone records at 64 kbps (`RECORDING_BITS_PER_SECOND`) and stops at 8:00. The hold lapsing mid-demo doesn't stop or lose the recording (the upload is accepted while the judge is still seated). If the upload fails at the table, the phone keeps the recording in its queue and sends it with `queued=1` once it is back online, at most 15 min after leaving the table; the transcript then reaches the evaluation through an edit (`talkProof`, §2). The outbox item for an evaluation carries `talkProof` with its highlights, and sends `highlights: []` (not nothing) when the judge removed every item.

**`POST /api/talk/recordings`** (judge session, same-origin, multipart, **fields first, audio last**)

- Fields, in this order: `projectId`, `mode`, `consentAt` (table mode, required) with **`sentAt`** (the phone's clock as the request leaves; the route moves `consentAt` onto the server's clock, `consentAt + (now - sentAt)`, before the visit check, `consentOnServerClock` in `lib/talk/service.ts`: the consent window below is judged on the server's clock, and a phone a few minutes fast or slow cannot fix that by asking the team again; without `sentAt` the stamp is taken as it is; the field is not kept and adonix never sees it), `queued` (`"1"`: a table recording the phone queued after a failed upload at the table, see the talk context), **then** `audio` (WebM/Opus, MP4/AAC or Ogg/Opus, 1 KB–5 MB). FormData sends parts in the order they were appended, so the phone appends the fields, then the audio. An `audio` part before `projectId` and `mode` is `400 BadTalkRequest` (nothing of it read); a field sent twice with different values is `400`; at most 16 KB of fields. A `durationSec` field is ignored.
- **Permission before the audio** (`readFieldsFirst`, `lib/talk/http.ts`): the body is read only up to the start of the `audio` part, and the no-count talk context (`purpose: "transcribe"`: the switch, the round, the visit, the opt-out, the placard rule, consent, the judge's transcriptions and the event's transcription budget), the receipt secret and the speech-to-text credentials are checked from those fields. A refused upload (403, 409, 429, 503) costs one small read; the audio is never buffered for it.
- **The phone records at 64 kbps** (`RECORDING_BITS_PER_SECOND`: MediaRecorder `audioBitsPerSecond: 64000`). 8:30 at 64 kbps is ≈ 4.1 MB, inside the 5 MB cap with room for the container; a browser's default 96–128 kbps would not fit (8:30 fits 5 MB only below ≈ 80 kbps) and would be `413 AudioTooLarge` before the 8:00 stop.
- The body is **streamed with a hard cap** (5 MB + 64 KB): `413 AudioTooLarge` the moment it passes, whatever `Content-Length` says (a declared oversize is refused before reading; a missing or lying one doesn't help).
- Order: the fields and the talk context with `purpose: "transcribe"` (all its refusals, whatever was sent; counts nothing), `503 TalkNotConfigured` / `TranscriptionUnavailable` (no receipt secret, no speech-to-text credentials), then the audio: `400 NoAudio`, `413 AudioTooLarge`, `400 EmptyAudio` (< 1 KB), `415 UnsupportedAudio` when the bytes aren't WebM (EBML `1A 45 DF A3`), MP4 (`ftyp` at offset 4) or Ogg (`OggS`), or a declared type isn't audio or isn't the type the bytes are. No type, or `application/octet-stream` (what multipart sends for a Blob without a type, e.g. one re-wrapped from IndexedDB), declares nothing: the bytes alone decide. Only then the spend (`kind: "stt"`, signed: one transcription and one of the event budget, atomically; `429 TranscriptionQuota` / `TranscriptionBudget`), then the vendor.
- Duration is the server's: Whisper's `transcription_info.duration`, else the last segment's end; over 8:30 (510 s) is `413 RecordingTooLong`. Transcripts are capped at 200 segments and 24,000 characters (later segments dropped), no segment starts after 9:00, ids `s1…` are unique. **No segment is over 1000 characters** (`MAX_SEGMENT_CHARS`, the same limit highlights and `talkProof` accept): a longer vendor segment, or Whisper's text-only answer, is split at a sentence end or a word boundary, each piece timed by its share of the text up to the next segment (or the end of the recording), and the ids renumbered `s1…`. The server never signs a transcript the highlights endpoint would refuse.
- Returns `TranscriptResult { projectId, mode, segments: { id, t, text, confidence? }[], durationSec, words, lowAudio, tooShort, engine, receipt, receiptExpiresAt }`. Segments have **no speaker field**.
- Speech to text: Cloudflare Workers AI `@cf/openai/whisper-large-v3-turbo` over REST (`CF_ACCOUNT_ID`, `CF_API_TOKEN`), `{ audio: <base64>, task: "transcribe", language: "en", vad_filter: true, initial_prompt, condition_on_previous_text: false, no_speech_threshold: 0.6, hallucination_silence_threshold: 2 }`, 25 s timeout. `initial_prompt` = "<project name>. Words you may hear: <vocabulary>": **no team names, no tagline**. No diarization option exists or is requested. `confidence` = exp(avg_logprob), capped at 0.3 when `no_speech_prob` > 0.6.
- `502 TranscriptionFailed` ("Couldn't transcribe. Your notes are saved."; the vendor call counted) and `413 RecordingTooLong` carry a **failure receipt** (`receipt`, `receiptExpiresAt`) for the evaluation's `recording: { status: "failed" }`; `503 TranscriptionUnavailable` without credentials (counts nothing, no receipt). **A vendor answer of the wrong shape is a vendor failure** (`parseWhisper`, `lib/talk/transcribe.ts`: `result` an object; `segments`, when present, a list of objects with a string `text` and finite numeric times and scores; `text` a string; `transcription_info.duration` a number; never coerced), and so is any other unexpected error after the spend: both answer `502 TranscriptionFailed` with a failure receipt, never a 500 without one. A vendor failure is logged by its kind only (`HTTP 500`, `SyntaxError`), never its message or body: a JSON parse error quotes the body, and the body is the transcript. In mock mode (the same gate: `GAVIL_MOCK=1` under `next dev` or vitest; never a deployed build, which gets `503 TranscriptionUnavailable` without Cloudflare credentials) it returns the fixture transcript for the project (`lib/talk/fixtures.ts`: NeuralMesh, EcoLens, PocketLab, Atlas; an EcoLens memo) and its duration, `engine: "fixture"`.
- **The audio is dropped in the same request**: held in memory for the one call, never written, logged or sent anywhere else.

**`POST /api/talk/highlights`** (judge session, same-origin, JSON streamed with a hard 128 KB cap; the `talkHighlights` server action does the same, in the same order: its own same-origin check on the request headers, then the role (a staff or admin session gets `{ ok: false, status: 401, code: "Unauthorized" }` like the route, and is never signed out; only an expired session takes the signed-out path), the same cap on its argument, and the judge the outbox item was saved under: `409 WrongJudge`)

- Body `HighlightsRequest { projectId, mode, segments (exactly as returned: ≤ 200, unique ids, 0 ≤ t ≤ 540, text ≤ 1000 chars, ≤ 24,000 chars in all), marks: seconds[] (≤ 50, ≤ 540), notes? (≤ 8000), receipt }`; `400 BadTalkRequest` / `ReceiptRequired` otherwise.
- The receipt: `403 BadReceipt` when it is forged or tampered, a failure receipt, for another project or mode, or the segments' hash differs (an edited, added or dropped segment); `403 ReceiptExpired` after 30 min. Then the talk context with the receipt's `visitId` (403/409), whose `judgeId` and `visitId` must equal the receipt's (`403 BadReceipt`: another judge can't use it).
- The **rule extractor always runs** (`lib/talk/extract.ts`: pure, deterministic, ~ms; the same code can run on the phone offline). Claude runs only when `context.llm`, there is enough speech (`tooShort` false), `ANTHROPIC_API_KEY` is set (else `fallback: "no-key"`), and the spend (`kind: "llm"`, signed, atomic) grants the call (else `fallback: "quota"` or `"budget"`).
- Errors: `{ error, message }` plus only `tableCode`, `expected`, `yourTable` (and a failure `receipt`). **A message or detail that repeats the request's text** (12 letters or digits in a row of the notes, the transcript or a kept highlight, or a whole short piece of 6 to 11; compared on letters and digits only, after the fold, so case, spacing, punctuation, letters pulled apart and invisible characters change nothing, and after undoing URL encoding (three layers, form `+` too), HTML entities, JSON / JS escapes and base64 runs; anything over 8 KB counts too) is replaced ("That request couldn't be used. Your notes are saved.") or dropped, whoever wrote it (`scrubText` / `safeDetails`, `lib/talk/http.ts`); the `talkHighlights` action does the same. **So does the `submitEvaluation` action**, whose request carries the notes, the kept highlights and a whole transcript (`talkProof.segments`, which `sensitiveOf` reads too): its error message is scrubbed, and from its details every string or key that repeats the request (at any depth) is dropped while the rest stays (`scrubDetails`: the phone keeps a refused evaluation's error whole in the outbox and shows it to staff).
- Returns `HighlightsResponse` = `TableTalkHighlights { version: 1, projectId, mode, source: "rules" | "llm", generatedAt, stats { words, durationSec, marks, lowAudio, tooShort }, oneLiner, howItWorks ≤ 3, stack ≤ 8, trackMentions, demo { status, evidence }, standouts ≤ 3, concerns ≤ 3 (kind open_question | limitation | didnt_work | prior_work | other), presenters, prizeSuggestions ≤ 1 }` plus `fallback?` (`off | no-key | quota | budget | timeout | error | refusal | max_tokens | invalid`) and `dropped?` (a count). Every item has `{ text, quote, segment, at, certainty: heard | unsure, speaker: team | judge | unknown, marked, state: "suggested" }`.
- A memo returns no presenters and no prize suggestions (every line is the judge's).
- **Never stored, never logged** (not the transcript, not the notes, not the output).
