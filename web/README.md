# Gav-IL web

The HackIllinois 2027 judging app (phone-first, for judges) and admin console (laptop-first, for staff and admins).
It runs on Next.js 16 App Router, React 19 and TypeScript, and deploys to Cloudflare Workers through OpenNext, the same way `HackIllinois/admin-site` does.
Data and auth come from [adonix](https://github.com/HackIllinois/adonix). Styling comes from `../design-system`. This app has no Tailwind and no MUI.

Read `../AGENTS.md` and `../design-system/README.md` before changing UI.

## Run it

```bash
cd web
cp .env.example .env.local      # GAVIL_MOCK=1 serves fixtures, no backend needed
npm install
npm run dev                     # http://localhost:3000  (PORT=3100 npm run dev for another port)
```

Then open `/login` and pick **Judge**, **Staff** or **Admin** under "Mock sign-in". Mock mode runs **only under `next dev` and vitest** (`GAVIL_MOCK=1` with `NODE_ENV` development or test): `next start` and a deployed build refuse to boot with `GAVIL_MOCK=1` (see Environment). The email code `123456` and the `demo-j1` link need `GAVIL_MOCK_DEMO=1` as well; without it codes are random.

## Deploy

Gav-IL is one Cloudflare Worker, `gavil`, built with OpenNext (`wrangler.jsonc`). **It needs the Workers Paid plan** (the Standard usage model): the Free plan gives a Worker 10 ms of CPU per request and ends a longer one with Error 1102, and the Table talk highlights run the rule extractor (`lib/talk/extract.ts`) on every request to `/api/talk/highlights`. The final review measured it on workerd (`wrangler dev`, on a busy laptop, so these are upper bounds): about 3 ms warm for a 42-segment transcript, 9 ms for 82 segments and 18 ms for the longest one the route accepts, with a first call of 120 to 140 ms. Anything that does real work per request (a page that calls adonix, a recording upload) is over 10 ms as well, so do not deploy `gavil` on Free. On Paid, `limits.cpu_ms` in `wrangler.jsonc` can raise the default 30 s of CPU per request; it does nothing on Free. Do these in order.

1. **Log in.** `npx wrangler login`, with an account that may deploy `gavil` (the HackIllinois Cloudflare account). Check out the repo with `design-system/` beside `web/`: `build:worker` runs `npm run sync` first.
2. **Mock mode never ships.** OpenNext bakes every `.env*` file it finds at build time into the Worker (`.open-next/cloudflare/next-env.mjs`), so a `.env.local` made with `cp .env.example .env.local` (it has `GAVIL_MOCK=1`) would put mock mode into the deployment, and the Worker refuses to start with it on purpose (`instrumentation.ts`): every request, `/api/health` too, answers 500. `npm run build:worker` therefore sets `GAVIL_MOCK`, `GAVIL_MOCK_DEMO` and `GAVIL_MOCK_TALK` to `0` for the build, which beats the file. Still, deploy from a checkout without a `.env.local` when you can.
3. **Vars** are in `wrangler.jsonc` and are not secret: `ADONIX_URL` (adonix), `GAVIL_ORIGIN` (our public origin, `https://judging.hackillinois.org`), and, for a staging adonix host, `GAVIL_ADONIX_HOSTS` (a comma-separated host allow-list). A staging deploy changes them there. The Gav-IL host must also be in adonix's `ALLOWED_WEB_HOSTS`.
4. **Secrets**, once per deploy target, each with `npx wrangler secret put <NAME>` (it asks for the value; `npx wrangler secret list` shows what is set):

    | Secret                          | Needed     | Value                                                         |
    | ------------------------------- | ---------- | ------------------------------------------------------------- |
    | `GAVIL_GRANT_SECRET`            | always     | 32+ random characters, Gav-IL only: `openssl rand -base64 32` |
    | `GAVIL_JWT_SECRET`              | always     | adonix's `JWT_SECRET`, copied, not generated                  |
    | `GAVIL_TALK_SECRET`             | Table talk | 32+ characters, the same value adonix has                     |
    | `CF_ACCOUNT_ID`, `CF_API_TOKEN` | Table talk | Workers AI speech to text                                     |
    | `ANTHROPIC_API_KEY`             | optional   | Claude highlights; the rule extractor runs without it         |

    Never `GAVIL_MOCK` or `GAVIL_MOCK_DEMO`: the Worker refuses to boot with either.

5. **Preview** before deploying: `npm run preview` builds and serves the Worker at http://localhost:8787 with wrangler. Wrangler reads secrets and var overrides from `web/.dev.vars` (gitignored), so for a judge session put `GAVIL_ORIGIN=http://localhost:8787`, `GAVIL_GRANT_SECRET=…` and `GAVIL_JWT_SECRET=…` there; without a `GAVIL_ORIGIN` of its own a preview uses the production origin for the staff Google sign-in callback and for the `Origin` it sends to adonix.
6. **Deploy between rounds, not during one.** A phone that opened Gav-IL before the deploy still runs the old build, and the new one no longer has the old build's server actions (Next.js answers `409 x-nextjs-action-not-found`, its client throws `UnrecognizedActionError`; the same for a chunk that is gone). Nothing is lost: every write was saved on the phone first, and each screen says "A new version of Gav-IL is ready" with a Reload button (`isStaleBuild`, `OutboxAlert`; the outbox stops, counts no attempt and runs no retry timer meanwhile). But every open phone is stuck until it reloads, so deploy before check-in or between Round 1 and Round 2, and tell the judging desk.
7. **Deploy.** `npm run deploy` (build, upload, switch traffic, then `npm run check:health`: it asks `/api/health` and the deploy fails when the answer is not `{"ok":true}`, so a missing secret stops here and not in front of a judge). The first time, attach `judging.hackillinois.org` to the Worker: Cloudflare dashboard → Workers & Pages → `gavil` → Settings → Domains & Routes. `npx wrangler rollback` returns to the previous version.
8. **Check it.** The deploy already ran this; to run it again: `npm run check:health`, or `curl -s https://judging.hackillinois.org/api/health`, which answers `{"ok":true}` (`GET /api/health`: no session, never calls adonix, never cached). A `503 {"ok":false,"problem":"config"}` means a required secret, public origin or safe adonix URL is missing or invalid; check `GAVIL_ORIGIN`, `GAVIL_JWT_SECRET`, `GAVIL_GRANT_SECRET`, `ADONIX_URL` and `GAVIL_ADONIX_HOSTS`. (Mock mode is a different failure: the Worker refuses to boot with it, so every URL, `/api/health` included, answers a plain 500 and no 503 JSON; see step 2.) Then `curl -sI https://judging.hackillinois.org/login` and read the headers below.
9. **Logs.** A sign-in link (`/auth/magic?token=…`, valid 15 minutes) and a placard scan (`/t/A12?k=…`) carry a token in the first request's URL, so Workers Logs must never hold a query string. `wrangler.jsonc` does two things about it. `observability.redact_query_string: true` is Cloudflare's own setting (wrangler's config schema: "whether query strings are removed from request URLs in logs and traces"), so the query string is stripped from the request URL on every log and trace record, exceptions and spans included. `observability.logs.invocation_logs: false` also turns the automatic per-request invocation log off, so a token does not depend on the redaction alone: with that log off, no request line, and so no query string, reaches Workers Logs. What the app prints (console output, uncaught errors) is still kept. Gav-IL's own code never logs a URL (the only `console.warn` calls are in `lib/talk/`, and print an error class or status, never a URL or content). **The cost:** the dashboard no longer lists one line per request with its status and duration; the Workers Metrics tab still counts requests, errors and CPU time. To see request lines during an incident, set `invocation_logs` to `true`, `npm run deploy`, and set it back afterwards; `redact_query_string` stays `true` either way, so the lines carry the path only. **Check it once, after the first real deploy:** open `https://judging.hackillinois.org/auth/magic?token=check` (or `/t/A12?k=check`), then find that request in the Workers Logs of `gavil` and confirm the record shows no `?token=` or `?k=`. Wrangler's local store (`npm run preview`, `wrangler dev`) does not apply the redaction, so a local run proves nothing about it. `npx wrangler tail` prints request URLs live and stores nothing: use it knowingly, not on a projector.

**Next.js 16 on OpenNext.** Next.js 15 left its support window in October 2026, and OpenNext refuses an unsupported Next.js unless it is told otherwise, so Gav-IL runs Next.js 16 (16.4.2) with `@opennextjs/cloudflare` 1.20.13 (it accepts Next.js `>=16.4.1`; `@opennextjs/aws` 4.1.12). `npm run build:worker` passes no version flag: if a build ever prints that the version is unsupported, update Next.js, do not add a flag. Three things differ from what the Next.js 15 build did; the first two were checked on the built Worker (`npm run preview`, a forged judge and admin session, a header matrix over 21 paths, Playwright at 390x844 and 1280x800):

- **The bundler is Turbopack**, the Next.js 16 default for `next dev` and `next build`. If a production build ever misbehaves, `next build --webpack` (the `build` script) is the way back and OpenNext builds it too. One difference shows in the CSP: with Turbopack the chunk `<script>` elements that Next.js adds after a client-side navigation carry no `nonce` attribute (webpack's loader put one on them). Every script in the server-rendered HTML still carries the request's nonce, `'strict-dynamic'` trusts the scripts a nonced script adds, and `'self'` covers a browser without `strict-dynamic`; the browser reports no violation on any screen. Do not "fix" it by loosening `script-src`.
- **The route gate stays `middleware.ts`.** Next.js 16 renames the file to `proxy.ts` and deprecates `middleware.ts` (the build prints a notice; it still builds and behaves the same), but `proxy.ts` runs on Node.js only. OpenNext runs a Node.js proxy on Cloudflare as an experimental path its own build warns "is not officially maintained by OpenNext maintainers", while the edge middleware is its main path, and everything in `middleware.ts` is edge-safe. So the gate was not renamed: a security gate stays on the supported path. Both were built and run: the same 21-path header matrix, the same gate answers (forged, expired and wrong-role cookies, `/auth/magic?token=`, the action-redirect for a dead session) and the same upload answers; `proxy.ts` makes the Worker 0.45 MiB larger gzipped (1.75 MiB against 2.20 MiB gzipped; Cloudflare's Worker size limit is 10 MiB on Workers Paid, the plan Gav-IL needs, and 3 MiB on Free). To rename later, once OpenNext supports Node.js middleware: `mv middleware.ts proxy.ts`, rename the exported function `middleware` to `proxy`, and change the `../../middleware` import in the middleware tests (`import { proxy as middleware } from "../../proxy"` keeps their bodies as they are) and the two `"middleware.ts"` file lists in `prod-deploy.test.ts` and `w3-env-docs.test.ts`.
- **`next lint` is gone**: `npm run lint` is `eslint .`. `eslint-config-next` 16 would also switch on the React Compiler diagnostics of eslint-plugin-react-hooks 7; they are off in `eslint.config.mjs` so the rules are the Next.js 15 ones.
- **Three things to know about `next dev`.** If a page hot-reloads over and over (a headless browser on `/judge` saw about five reloads a second, with `Compiled in 2ms` in the terminal after every load), stop the server and delete `.next/dev`: a stale Turbopack dev cache left behind by earlier runs did this once during the upgrade, and a fresh one cured it, with or without `WATCHPACK_POLLING`. And a dev run writes an untracked `web/AGENTS.md` (Next.js's own agent note; `agentRules: false` in `next.config.ts` stops it, or delete it): it is not part of this repo's instructions, which are `../AGENTS.md`. The third: a tap on "I’m at the table" within about a second of the check-in redirect (which hops `/judge/countdown`, then `/judge/evaluate`) can log React's `This library called use() to suspend in a previous render but did not call use() when it finished` and show "1 Issue" in the dev overlay. Every frame of it is inside `next`'s own router (this app never calls `use()`), the check exists only in React's development build (`react-dom-client.production.js` does not contain it), so it is dev-console noise, not a defect of the product. It is a race between the redirect's navigation and the tap's server action in Next 16.4.2 dev (it did not show at a normal pace, or in the headless click-through of this run at 0 and 0.5 s); a production build never logs it. Do not add code to hide it; if a newer Next.js removes it, nothing here changes.

**Security headers** are on every response, in four places that share one source, `lib/security/headers.ts` (pure functions, unit-tested). A path is covered by exactly one of the first two (a header both set would be appended by OpenNext, and `same-origin, same-origin` is not a valid COOP); `lib/__tests__/prod-headers.test.ts` checks that they are disjoint:

| Where                                               | What it covers                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `middleware.ts`                                     | every page, route handler, redirect and 404, dotted paths included (`/robots.txt`, `/t/A12.png`, `/judge.json`): the headers, the per-request-nonce `Content-Security-Policy` (also sent to Next.js as a request header, which is how it puts the nonce on its scripts) and the path's `Referrer-Policy` (`no-referrer` on `/login`, `/auth/*` and `/t/*`). The route gate runs unchanged inside it. Not matched: `/_next/static/*` and `/_next/image`                                                                                                                            |
| `next.config.ts` `headers()`                        | exactly what the middleware does not match: `/_next/static/*` and `/_next/image`, for a plain `next start`                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `public/_headers`                                   | what Cloudflare serves from its asset store before any code runs (`public/`, `/_next/static/*`); generated by `cloudflareHeadersFile()` (`npm run headers:file` rewrites it; Node 22.6 or newer), and a test fails when it drifts. **Part of the deploy: `web/public/_headers` must be committed**                                                                                                                                                                                                                                                                                |
| `lib/security/worker.mjs` (`wrangler.jsonc` `main`) | OpenNext's handler, wrapped. Some answers come from the framework layers before any app code runs (Next's trailing-slash 308 for `/judge/`, `/_next/image`, a 404 under `/_next/data/`). Anything still missing the six headers gets them here (`lib/security/edge-headers.ts`: add only what is absent, never double), and the `x-middleware-*` hand-off headers OpenNext leaves on a redirect are dropped (`x-middleware-set-cookie` repeated the `gavil_magic` cookie where a script can read it). It needs `.open-next/worker.js`, so build with `npm run build:worker` first |

A `<Link>` to a route handler that redirects (the staff "Sign in with Google" button goes to `/auth/google`, which answers 303 to adonix) is prefetched by Next.js as a script `fetch()`, and `connect-src 'self'` refuses the cross-origin hop. The middleware therefore answers a scripted GET of any `/auth/*` handler with an empty 204 (`lib/security/hard-navigation.ts`), which Next.js turns into a normal browser navigation: no CSP violation, no prefetch that signs anyone in or out, and `/auth/magic` (a real page) is left alone. Next.js strips its own `RSC` and `_rsc` markers before middleware runs, so the test is the browser's `Sec-Fetch-Dest: empty` (a navigation sends `document`) and the router's `Next-Url`. A plain `<a>` for that button is still the cleaner markup (UI stage).

The values: HSTS two years with subdomains (never under `next dev`), `nosniff`, `X-Frame-Options: DENY`, COOP `same-origin`, and `Permissions-Policy: camera=(self), microphone=(self), geolocation=(), payment=(), usb=()`: the camera is the in-app placard scanner and the microphone is Table talk, so never deny either. The CSP allows only this origin's scripts (plus the nonce and `strict-dynamic`), styles, images, fonts and `connect-src`, and names adonix in `form-action` (staff Google sign-in leaves through it). Under `next dev` it also allows `unsafe-eval` and `ws:` for hot reload. `next dev` (Turbopack, `npm run dev`) additionally drops `strict-dynamic`, because Turbopack inserts some route chunks without the nonce and same-origin scripts must count there; `next dev --webpack` and every production build keep it. `ADONIX_URL` must be an `http(s)` URL with a plain host (letters, digits, dots, hyphens, or a bracketed IPv6); production requires HTTPS and a host in `GAVIL_ADONIX_HOSTS`, while HTTP localhost is only allowed in development/test. Anything else leaves adonix out of `form-action` (staff Google sign-in is then refused by the browser) instead of letting the value change the policy. A new third-party origin means editing `contentSecurityPolicy` and its test; do not loosen `script-src`.

**For the UI stage, before the placard scanner and Table talk ship.** Both are allowed by the policy as it stands (`camera=(self)` and `microphone=(self)` in the Permissions-Policy; `blob:` for `media-src`, `worker-src` and `img-src`; recordings upload to this origin, so `connect-src 'self'` covers them). One thing is not: a WebAssembly QR decoder (a ZXing build, the fallback for iOS Safari, which has no `BarcodeDetector`) cannot compile under this `script-src`, and a CDN-hosted `.wasm` file cannot load under `connect-src 'self'`. Self-host the decoder, add `'wasm-unsafe-eval'` to `script-src` in `contentSecurityPolicy` (it allows WebAssembly only, not `eval()`) and extend `lib/__tests__/prod-headers.test.ts`; the typed table-code fallback needs none of it. Recording uploads go through the middleware like every other request, so `next.config.ts` caps what Next.js buffers for a route behind it at 6 MB (`experimental.proxyClientMaxBodySize`, the Next.js 16 name of `middlewareClientMaxBodySize`, just above the route's `MAX_AUDIO_BYTES` + 64 KB; a test keeps them in step).

**Installed app.** `app/manifest.ts` ("Gav-IL judging", opens `/judge`, standalone) takes its colours from `lib/security/install.ts`: the sunset `ground` and `surface` tokens, which `lib/__tests__/prod-manifest.test.ts` checks against `../design-system/tokens.json`. `public/icons/h-mark.svg` is `design-system/assets/brand/h-mark.svg` unchanged; `icon-192.png`, `icon-512.png` and `apple-touch-icon.png` are that mark centred on the `ground` colour (a white mark on a transparent icon vanishes on a light launcher), exported once from the SVG, never redrawn.

**When the page itself breaks.** `app/global-error.tsx` is the last resort (root layout threw): its own `<html>` (in the theme cookie's theme), a poster-paper card, Try again (reloads) and a link to `/login`, no error text. `app/error.tsx` (which catches the `/judge` and `/admin` layouts, where adonix is called first), `app/judge/error.tsx` and `app/admin/error.tsx` never show an error's message or stack and refresh the route before retrying (`lib/security/retry.ts`). A refresh the network cannot answer would make Next.js navigate the document itself, and the browser's own offline page would replace the app, so: while `navigator.onLine` is false the copy says "You're offline" and Try again is disabled (the `online` event enables it), and on Wi-Fi that is joined but has no uplink (it still reads online) Try again first asks `/api/health` (no session, never adonix) and refreshes only when something answered; no answer shows the offline copy and leaves the button for the next try.

## How auth works

The session is the adonix JWT itself. It is stored in the httpOnly cookie `gavil_session` and is only ever read on the server. Pages and server actions call adonix with `Authorization: <jwt>`.

- **Staff and admins:** "Sign in with Google" links to `/auth/google?next=…`, which mints a one-time `state` nonce (httpOnly cookie) and sends the browser to `{ADONIX}/auth/login/google/?redirect={origin}/auth/callback?next=…&state=…`.
  adonix runs Google OAuth (`@hackillinois.org`), then redirects back.
  `/auth/callback` reads the token from `?token=` or from adonix's `jwt` cookie (in production that cookie is scoped to the registrable domain, so `*.hackillinois.org` receives it) and sets `gavil_session`.
  The Gav-IL host must be in adonix `ALLOWED_WEB_HOSTS`.
- **Judges:** there is no password. Judge sign-in is modelled on adonix's sponsor flow, and the design doc covers it in §7.
  `/login` ("Howdy, judge.") takes an email and calls `POST /auth/judge/verify/` with `{email}` in the body, which always reports success. The email contains a one-tap link and a 6-digit code.
    - The **code** goes to `POST /auth/judge/login/`. Each code allows 5 tries; the form shows "N tries left", then "Send a new code".
    - The **link** (or the desk QR) is redeemed in two steps. `/auth/magic?token=` only looks the link up (`POST /auth/judge/link/`) and asks "Sign in to judge as <email>?". **Continue** POSTs the token to `/auth/magic/redeem`, which calls `POST /auth/judge/redeem/`. Nothing is redeemed on a GET.
    - Used or expired links show "Link expired."
    - Auth pages send `Referrer-Policy: no-referrer`.
- **Judge tokens** carry `role: JUDGE`, `eventId` and `assignmentId`. adonix checks `JudgeAssignment.revokedAt` on every call. A 401 inside a judge server action that carries nothing to lose (the check-in button, the help request) signs the phone out in the action itself (cookie cleared, `/login?error=revoked`). A 401 inside a **write** (evaluation, skip, vote, ranking, draft, "can't find it", check-in) or a poll that fires while the judge types is answered as data (`SessionEnded` / `Revoked`) and touches no cookie: the screen keeps the write on the phone first, then leaves through `GET /auth/logout`; if the phone can't keep it, the screen stays and offers "Sign in again" (CONTRACT §3, CFX 2).
- **Every token is verified before it becomes a session, and on every request after:** the Google callback (with its one-time `state`), the code login and the link redeem (`verifyJudgeToken`: also a JUDGE token with its event and assignment) verify the JWT before setting `gavil_session`; middleware and `getSession()` verify it again per request (`verifySessionCached`: the HS256 signature with `GAVIL_JWT_SECRET`; only development/test without a secret uses an adonix `GET /auth/roles/` round trip; `exp` required and capped; a positive verdict for 60 s or a negative verdict for 10 s, with concurrent checks coalesced). Production requires `GAVIL_JWT_SECRET`. A cookie that only decodes opens no shell and reaches no server action.
- **Tokens leave the URL on arrival:** `/auth/magic?token=` moves the token into an httpOnly cookie and redirects to `/auth/magic`; `/t/A12?k=` swaps `k` for a scan grant (below); `/login?next=` never carries either.
- **Mock mode** (`GAVIL_MOCK=1` under `next dev` or vitest only): `/auth/mock?role=judge|staff|admin` sets a token HS256-signed with the dev secret. adonix would reject that token.

The endpoints `/auth/judge/*`, `Role.JUDGE` and `/judging/*` do not exist in adonix yet. `lib/api/CONTRACT.md` specifies them, including the Origin check on writes, idempotent `clientId` writes and Visit leases.

## How the design-system sync works

`../design-system` is the source of truth. `scripts/sync-design-system.mjs` runs before every `dev` and `build` and does three things:

1. It compiles `tokens.json` to `app/styles/tokens.css`.
   This is a line-for-line port of `compile_tokens()` in `design-system/scripts/build_previews.py`: `:root, [data-theme="sunset"]` holds the default theme, `[data-theme="night"]` holds the overrides, and a trailing `:root{}` holds spacing, radius, size, motion (with its reduced values under `prefers-reduced-motion` and `[data-motion="reduce"]`), asset, font and `--type-*` / `--tracking-*` tokens.
   The output is identical to `.preview/tokens.css`.
2. It copies `components/bundle.css` to `app/styles/gavil.css` and drops its Google Fonts `@import`, because `next/font` self-hosts the fonts.
   `app/styles/app.css` points the `--font-*` tokens at the `next/font` variables.
3. It copies the 2027 brand art the `--art-*` tokens name (`assets/brand/…`, originals and `derived/` WebP) to `public/brand/` and points the tokens' urls there. The art is never redrawn or recoloured; a test checks that every `--art-*` url resolves.

All outputs are committed, so a checkout without `../design-system` (CI, or a standalone GavIL repo) still builds; the script then warns and keeps the committed files. You can point it elsewhere with `GAVIL_DESIGN_SYSTEM=path`. Run `npm run sync` again whenever the design system changes (`predev` and `prebuild` do), then port what `bundle.js` changed.

The components in `components/` are hand ports of `bundle.js`. When `bundle.js` changes, port the change: keep the class names, ARIA and copy identical. Three differences from the design system are deliberate, each in a test: the skip sheet says what the picked reason does and keeps a reason that needs the table checked first in the list, disabled, with why (`cweb-skip-copy`, the design system's sheet hides such a reason); a policy lock that stops a _memo_ also names where the judge sits (`TalkLock "seat"`, no counterpart in the static previews); and the Round 2 board's "Demo" link defaults to the nominee's Devpost page (`cweb-round2-demo`).

Theme: `<html data-theme>` comes from the `gavil_theme` cookie (`sunset` by default, or `night`). The "Night theme" toggle on My notes and in the admin header (`app/ThemeSwitch.tsx`) writes it (a year, `SameSite=Lax`, `Secure` on https) and sets `data-theme` at once; the app does not follow the phone's own light or dark setting, because night is the same cream posters on a darker ground, not a dark mode. `app/global-error.tsx` (the last-resort page, which replaces the layout) reads the same cookie from the page (`document.cookie`, guarded), so a crash keeps the chosen theme: the server draws sunset there (no cookie reaches it) and the browser draws the chosen one. The browser's address-bar colour (`viewport.themeColor`, the manifest's `theme_color`) is the `surface` token, poster-paper cream in both themes, so it needs no switch. The control is not designed in the design system yet (followup).

- Visits have two phases. En route: 4 minutes to reach the table ("Can't find it?" at 3), never extended; if it runs out the table goes back to the queue with no penalty. No placard = confirm by team name: allowed, recorded and staff tasked, and that evaluation's **nominations are held** until the placard is scanned at that visit (within 10 min of Submit) or staff press "Placard OK" on the task; the notes count either way.

When the phone is on the compare, wait or done screen the scan goes there (code only) and is sent once to the code-only check. A scan whose POST gets no answer is never queued (its `k` lives only in the 120 s grant): the judge types the check instead. The placard of the judge's last, name-only table, scanned within 10 min of its Submit from whatever screen the phone shows, releases that table's held nominations (`409 EarlierTable`, no wrong code at the current table).
