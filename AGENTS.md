# AGENTS.md — Gav-IL (HackIllinois 2027 judging + admin platform)

Instructions for any coding agent (Claude Code, Codex, Cursor, OpenCode, Muse) working in this repo.
Humans: read this too. It is the shortest description of how we build here.

## What this is

Gav-IL replaces 2026's spreadsheet-driven judging. Two surfaces, one design system:

| Surface | Users | Device | Core jobs |
|---|---|---|---|
| Judge app | ~40 volunteer and sponsor judges | **Phone first** (390px), one hand, loud room, flaky Wi-Fi | Check in → go to a table → check the placard → evaluate → compare last two (pairwise) → nominate for prizes → Round 2 ranking |
| Admin console | Staff + admins | Laptop first, must not break on a phone | Coverage, anti-cheat flag review, judge/room assignment, deliberations, admissions, reimbursements |

Terms are fixed. Never mix them:
- **Path**: Pro or General.
- **Track**: company-sponsored, e.g. Stripe or Modal.
- **Prize**: HackIllinois, company or MLH.
- Judges *nominate* and *compare*; they never "rate". "Score" is an admissions word only. Table talk highlights *describe*: they never compare, nominate or pick a winner. Tests scan for this (`web/lib/__tests__/cfin-terms.test.ts`, and the judge-words guard in `design-system/tests/`).

## Commands

```bash
cd design-system
python3 scripts/generate_component_docs.py   # regenerate component READMEs, previews, index.d.ts (--check: write nothing, exit 1 on drift)
python3 scripts/build_previews.py      # compile tokens + wrap every preview
python3 -m http.server 8765            # then open:
#   http://localhost:8765/.preview/                     all previews, every theme
#   http://localhost:8765/.preview/p/JudgePrototype-sunset.html
#   http://localhost:8765/tests/                        test suite (add ?theme=night)
node scripts/run_tests.mjs             # the same suite headless in every tokens.json theme, about 7 minutes each (--theme=plain for one)

cd ../web
cp .env.example .env.local   # GAVIL_MOCK=1: fixtures, no adonix needed (next dev and vitest only)
npm install && npm run dev   # http://localhost:3000, then /login → "Mock sign-in"
npm test                     # vitest
npm run typecheck && npm run lint && npm run format:check
npm run build:worker         # the Cloudflare Worker (npm run preview runs it locally; deploy steps: web/README.md)
```

The test page title becomes `PASS n/n` or `FAIL x/n` (it stays "Gav-IL tests" until the last check). **Every theme (sunset, night, plain) must pass before you call UI work done.** `npm run sync` in `web/` copies the design system in before every `dev` and `build`; run it after a design-system change, or the drift tests fail.

## Rules

1. **Tokens only.** No hex, px font sizes or shadows in components or screens; use `var(--token)`. To add a value, add a token to `tokens.json` with a `usage` note, then use it.
2. **Brand comes from Figma, not memory.** The source is the *HackIllinois 2027: Design System* and *Registration* files. Never redraw the logo, longhorn, characters or painted backgrounds; export them as assets.
3. **Phone first.** Every judge screen works at 390×844 with no horizontal scroll. Judge controls are ≥ `tap-min` (48px); `sm` buttons only in dense admin UI. Text fields use 16px text (no iOS zoom).
4. **Contrast is tested.** Text ≥ 4.5:1 and controls/focus ≥ 3:1 in every theme. Content goes on cards (`surface`: cream poster paper in the brand themes, white in Plain); only titles, eyebrows and ledes sit on `ground`.
5. **Every state is designed.** Loading, empty, error, offline, time-up, permission-locked, undo. If you add a flow, add its failure states and a test.
6. **Accessible by construction.** Radiogroups and tabs follow WAI-ARIA APG (one tab stop, arrow keys). Dialogs are `role=dialog` + `aria-modal`. Live regions announce state changes, never every timer tick. All motion stops under `prefers-reduced-motion`.
7. **Components are controlled-friendly.** Accept `value`/`onChange` (or `default*`), re-sync from props, expose every action as a callback. Never ship a button without a handler prop.
8. **Permissions come from one matrix** (`design-system/README.md` → Admin rules). Encode it in tab state, row state and button state together.
9. **Change the generator, not the output.** Component `README.md`, `preview.html` and `index.d.ts` come from `scripts/generate_component_docs.py`; edit it and rerun. The JudgePrototype, JudgeJourney, AdminConsole and Cover previews are hand-written.
10. **Small, reviewed changes.** Run the suite, then ask a second agent (Codex, Cursor, OpenCode, Muse or Agy; the free OpenCode and Kilo models when a quota is out) to review changes against these rules before merging. Check every finding against the code before fixing it, and keep each round's consensus in `docs/reviews/`.
