# Button

One action per tap. Gold primary for the step forward; an inked secondary for alternatives; ghost (text) for low-stakes escape hatches; solid danger only for the destructive commit itself.

- **Provide:** `children` label (verb first: "Submit evaluation", never "OK"), optional `icon`/`iconRight` (an Icon name), `variant` (`primary` `secondary` `ghost` `ghost-danger` `danger` `wood`), `size` (`sm` admin-only, `md`, `lg` for the single forward action on a judge screen), `shape` (`back`|`next`), `block`, `loading`, `settle` + `settleKey`, `btnRef`.
- **`wood` is the 2027 plank**, not a flat brown: the Registration plank art (`art-plank-flat`; with `shape` `back` or `next`, the arrow planks `art-plank-point-left` / `art-plank-point-right`) drawn as a 3-slice `border-image`, so the chamfered ends keep their cut at any width and only the grain between them stretches. Lettering is `on-wood` cream with the carved `shadow-sign` edge (cream on the plank's grain, under the `plank-scrim` veil, is at least 4.8:1 on every pixel under the letters, measured on real screenshots). The plank is its own ground, so it reads on paper, on the painted ground and on a wood bar. The clip-path takes the art's own cut (`plank-cut-x`, `plank-cut-y`, `plank-tip`), so the hit area follows the plank. Its focus ring is a cream (`on-wood`) band, 3px wide, that follows the plank's own cut (the chamfer or the arrow) **one `stroke-focus` in from the edge**: the plank keeps its dark edge outside the ring, so on a paper card it never reads as the plank shrinking (a ring flush with the edge is cream on cream, 1.04:1); it is a pseudo-element, the art paints over an inset shadow. Back and Next carry `tip + space-3` of padding on both sides so the ring's notch never touches the label. Disabled is the readable sunken plate, never faded art. Use it for navigation that is not the one forward action: Back, All applicants, Scan check-in QR.
- One `primary` per screen. On judge screens the primary sits in `ActionBar`, on the right, and is `lg`.
- Every size meets `tap-min` (48px) except `sm`, which is for dense admin tables only. Labels use `--type-button` (ghosts too).
- Press: scale to `press-scale` in `dur-press` (80ms), release in `dur-release` (160ms). No OS tap flash; hover only on devices that hover.
- `loading` keeps the fill, shows a spinner and the label, sets `aria-busy` and blocks re-entry. Disabled never fades: it becomes a readable sunken plate (wood-deep on wood), so any text on it still passes 4.5:1. If a disabled button carries an instruction, it must read on its own.
- `settle`: the button ignores pointer taps for `dur-settle` (450ms) after it appears and whenever `settleKey` changes, and absorbs them (nothing behind it gets the tap). Put it on any control that appears where the judge just tapped (the next project's Submit, Undo, Next table) so a double tap never acts on something unseen. Keyboard and assistive-tech presses (click `detail` 0) always act: focus only lands on a new control when the app moves it there, so the press is deliberate. A held Enter or Space never auto-repeats into a button (any button, settling or not). When two screens put different actions in the same slot ("Start Round 2" then "Submit my ranking", "Submit my ranking" then "Change my ranking"), give each its own `settleKey`: the same button instance only re-settles when the key changes.
- Under reduced motion the `loading` spinner stays still (its iteration count is the `loop` token, 0 there): the label and `aria-busy` say it is busy.
- `danger` (solid) is the commit inside a confirm; the trigger that opens the confirm is `ghost-danger`. Both live on paper (rows, cards, confirms), never on ground. Skip is reversible: `ghost`, never danger.
