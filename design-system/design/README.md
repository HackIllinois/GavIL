# Gav-IL spec sheet (OpenPencil)

`gavil-spec.fig` is a Figma-format spec of the design system, generated from the tokens, the current components and the real 2027 brand art.
It is not hand-drawn: change `tokens.json`, the components or the brand folder, rerun the generator, and the sheet follows.
The specimens are built from the same numbers, words and art the components use (the sheet reads `bundle.css`, `bundle.js`, the prototype previews and `assets/brand/` at run time); where it cannot read a rule it draws it by hand and says so under "How it is drawn".

## Variables

Every fill and stroke is bound to a color variable, and every text layer to a font-size and font-family variable. The exceptions are in "How it is drawn": the wide wood bars are a gradient (a gradient paint cannot bind its stops), and the drop shadows are effects.

- `Gav-IL color · Sunset` and `Gav-IL color · Night`: one collection per theme, one variable per color token (`color/ground`, ...), plus `derived/...` variables for tints composited over paper, pressed fills (`gold x0.94`) and the brand SVGs' own colors (`derived/brand/#231F20`, the longhorn). OpenPencil has no per-frame variable modes and the sheet shows both themes side by side, so each theme's stages bind to their own collection. 80 variables each, and 27 more in Sunset: the wood-grain colors of the three vectorized planks, which Foundations draws once, on the sunset side.
- `Gav-IL numbers`: spacing, radius and size tokens, `type/<style>/font-size` and `type/font-family/<key>` (69 variables). 256 in all.
- White brand art (the lockup, the H mark) is bound to `color/on-ground`.
- A fill that paints nothing (opacity 0) sits on every plank button, signpost board and plate: it names the color the text sits on, so the contrast lint can read the chain (the art itself cannot be read).

## Regenerate

```bash
cd design-system
~/.bun/bin/bun scripts/make_spec_sheet.mjs              # design/gavil-spec.fig + design/png/*.png, about 60 to 80 seconds on an idle machine (about 2.5 minutes while the test suite runs, and up to a minute more when design/brand-raster/ is empty)
~/.bun/bin/bun scripts/make_spec_sheet.mjs --only=buttons,placard   # subset -> design/gavil-spec.partial.fig + those PNGs
~/.bun/bin/bun scripts/make_spec_sheet.mjs --check      # audit only, writes nothing: contrast pairs, copy drift, state coverage, brand files
~/.bun/bin/bun scripts/make_spec_sheet.mjs --check --copy   # also list the specimen strings that are not found in the sources
~/.bun/bin/bun scripts/make_spec_sheet.mjs --strict     # a full run that also exits non-zero on any audit problem (adds the placard fit and the Table talk card fit audits)
SPEC_OUT=/some/scratch/dir ~/.bun/bin/bun scripts/make_spec_sheet.mjs   # write the sheet, the PNGs and the raster cache somewhere else (a trial run)
```

Pages for `--only`: `foundations buttons inputs judge talk placard screens`. Needs bun and `@open-pencil/core` and `opentype.js` installed globally with bun
(`bun add -g @open-pencil/cli`). The three character SVGs are rasterized once with Playwright (from `demo/node_modules`) into `design/brand-raster/`;
if Playwright is missing their tiles are labelled placeholders. Every other image (the originals and the `derived/*.webp` files) is decoded with the headless CanvasKit that OpenPencil ships and placed as PNG: the same pixels.

Exit codes: `0` fine (a plain full run exits 0 even when the audit reports problems, so a final rerun is never blocked by a component gap) · `1` the audit found a problem in
the sheet itself under `--check`/`--strict` (a missing token or brand file, copy drift, a component state with no specimen, a failing contrast pair), or the run was aborted ·
`2` bad arguments (an unknown flag, an unknown or empty `--only` page: nothing is written) · `3` `--check`/`--strict` found **only component gaps in `components/`**: the sheet is
right, and what to change in bundle.css or bundle.js is printed in the problem (see "Component gaps"). Both 1 and 3 are non-zero.

**A run that cannot make a faithful sheet stops and leaves the sheet alone.** Fonts come from Google Fonts on first use and are cached in
`~/.cache/gavil-spec-fonts` (set `SPEC_FONT_CACHE` to move it), so only the first run needs the network. If a face cannot be loaded, or any text layer cannot
be shaped, the generator prints `ABORTED: ...`, exits 1, and does not touch `design/gavil-spec.fig` or `design/png/*.png`: everything is produced in memory
and written (to a temp file, then renamed) only after every check has passed. Probed with a dead proxy and an empty cache: exit 1, existing files byte-identical;
with a dead proxy and a full cache: exit 0 and a complete sheet.

Inspect and check the result (the CLI must run under bun, its shebang is `node`):

```bash
op() { ~/.bun/bin/bun ~/.bun/bin/openpencil "$@"; }
op info design/gavil-spec.fig
op pages design/gavil-spec.fig
op tree design/gavil-spec.fig --page "Table talk" --depth 2
op lint design/gavil-spec.fig                 # --preset accessibility, --json
op analyze colors design/gavil-spec.fig       # also: typography, spacing --grid 4
op variables design/gavil-spec.fig
op export design/gavil-spec.fig --page "Buttons" -o buttons.png   # (PDF export and --thumbnail do not work headless)
op eval design/gavil-spec.fig -c 'return figma.root.children.length'   # eval prints only what it returns; for a script file: cat x.js | op eval design/gavil-spec.fig --stdin
```

What the generator reads at run time, so the final rerun picks up finished components: `tokens.json` (colors, type, spacing, sizes including the signpost fit numbers `sign-glyph`, `sign-fit-min`, `sign-fit-chars`, the `asset` group with the plank numbers `plank-cap-flat`, `plank-cap-arrow`, `plank-tip`);
`components/bundle.css` (button variants, heights, paddings and cuts, the phone rule of `.gv-select`, and the focus band of the wood button: its colour and width for the audit, its three polygons for the drawing); `components/bundle.js` (icon paths; the consent script, team notice and retention line, which it follows through the
named constants `POLICY_SCRIPT`, `POLICY_NOTICE` and `RETENTION`; the state lists of TableCheck and TableTalk; demo and recall labels); `components/JudgePrototype/preview.html` and `components/AdminConsole/preview.html` (screen button labels, the Round 1 complete wording,
the Settings switches and the confirm sentences); `assets/brand/*` (originals, `derived/*.webp` and `derived/geometry.json`) and `MANIFEST.md`.

**A thing that went missing is never silent.** A token that disappears is drawn magenta with a warning. A brand file the sheet places by name that is not in `assets/brand/` is a warning, and
`--check`/`--strict` count it as a problem: the logo, signposts, backgrounds and characters become a **labelled placeholder** (a box naming the file; the sheet never typesets a stand-in wordmark, AGENTS.md rule 2),
a plank that cannot be cut falls back to the flat `wood` token fill, and a garland, star or prop is left out. Probed on a scratch copy with `derived/plank-flat.webp` and `hackillinois-lockup.svg` deleted: three warnings (the plank, the lockup's placeholder and its missing tile in Brand assets), `--check` exit 1, a plain run exit 0 with the placeholder in
the app bars. A copy extraction that finds nothing (the consent script, the notice) shows a bracketed marker, not an old sentence.

## What is checked on every run

- **State coverage.** bundle.js documents `state: idle | consent | ...` above `TableTalk` (18 states) and `state: idle | scanning | ...` above `TableCheck` (12). The generator reads those lists, records which states its
  specimens show, and reports a state with no specimen (and a specimen of a state the component no longer lists). Last run: TableTalk 18/18, TableCheck 12/12.
- **Copy.** `S()` guards 115 hand-typed UI literals: each is looked up in `bundle.js`, the JudgePrototype `preview.html` or the AdminConsole `preview.html`; if a component is reworded the literal is reported as `copy drift` (an exit 1 under `--check`/`--strict`)
  instead of the sheet silently keeping the old words. Strings that the components build from pieces (`'Right table: ' + code + ', ' + name + '. Notes are open.'`, `'Revoke ' + name + '?'`) are guarded piece by piece. As a coverage count, of 326 distinct specimen strings on the
  Inputs, Judge, Table talk, Key screens pages and the placard sheet, 267 appear verbatim in the sources or contain a guarded literal; the other 59 are specimen data (project names, quotes, times, team names), the consent script
  and notice (extracted at run time), and a few admin selects. `--check --copy` lists them. Captions, notes and headers written for the sheet itself are not UI copy and are excluded.
- **Contrast.** 54 pairs x 2 themes (text 4.5:1, controls and rings 3:1): see "Component gaps". The run prints the tightest pass of each kind (`lowest passes: ...`), measured from the tokens: today text is `success on success-tint` at 4.57:1 and controls are `control border on sunken paper` at 3.79:1 (`pro on pro-tint` is 5.03:1). Every pair has its own tile label (two tiles that read alike are reported as a problem: the two `on-wood-soft` tiles once did). The signpost lettering (`ink-sign` over the tan art, 4.3:1 on the darkest grain without the glow, 5.5:1 with it) is measured on the art's own pixels by the component's suite, not here.
- **Fit of the Table talk cards at 390.** After layout the generator measures every descendant of a `TableTalk` card against the card's padding and reports a control that spills out (the caption says so, and `--strict` exits 3). See "Component gaps". A fix that lands in `bundle.css` is picked up by itself: see item 3 below.
- **Layout of the saved file** (checked by hand with `op eval`, not by the generator): no text layer runs outside its parent frame (0 of 3,928 on the last run; the scan is a `findAll` over TEXT nodes that compares `x + width` and `y + height` with the parent's size, 1.5px tolerance). The same scan over the frames, rectangles and ellipses inside frames (5,193 checked, skipping the page's own top-level frames) flags 28 frames, every one by design (the 4 memo retry buttons that used to be 23px past the card are gone: item 3 below): **16 CompareCard `Order ticket` frames, 12px above their card** (the ticket hangs over the card's top edge, as `.gv-compare__order` does; 8 on the Judge page, 8 on the Key screens), **6 pieces of key screen 5 pinned above the clipped phone frame** (the scrolled evaluate screen: the Wayfinding plank 193px, the TableCheck strip 125px, the project header 45px, all under the app bars) and **6 `Stamp` frames 1.6 to 2.3px below their row** (the stamps are tilted -2 degrees, which the unrotated frame box does not include). Nothing else is flagged, no empty text layer, and the stored geometry is the generator's own (the scans read `x`, `y`, `width` and `height` from the saved file). **A headless re-export of the saved `.fig` does not match the PNGs**: `op export design/gavil-spec.fig --page ...` re-lays out the auto-layout rows itself and differs from the generator's render in 1.1% (Placard), 4.4% (Buttons, Key screens) and 10% (Table talk) of pixels (a channel sum over 48), visibly in rows that centre an icon, a word and a number (the recorder's top line sits staggered, with the dot lower and the time higher). The previous sheet re-exports the same way (4.7% on Buttons), so it is not new, and the cause is not established (the CLI may lay out before its fonts are measured). The PNGs in `png/` are the generator's render with the real fonts, which is what the numbers above describe; how the file looks when opened in the OpenPencil app has not been checked. Re-run after any change; the scan scripts are short.

## How it is drawn, and what is approximate

- No clip-path in OpenPencil: chamfered buttons, arrows and the ticket stub are vector plates behind the label, created after the layout pass has measured their frame (the renderer caches a vector's path by node id, so a plate is never resized after its first render). Focus rings are stroke-only vectors inset from the plate, except the wood plank's: a filled band polygon read from bundle.css (see "Component gaps", item 1).
- **The planks are the real art, cut to size.** A wood button, Back, Next and the inline Wayfinding sign use `derived/plank-flat.webp`, `plank-point-left.webp` and `plank-point-right.webp` as bundle.css does: a 3-slice (`border-image`) where the two end caps keep their cut and proportions (`plank-cap-flat` 68, `plank-cap-arrow` 96 of the 192px art, drawn at the control's height) and only the grain between them stretches, with the plank-scrim veil (`rgba(74,42,22,.4)`, inset by the stroke, fading to nothing across each cap) painted over it. The generator does this with the headless CanvasKit on the exact pixels (nothing is redrawn or recolored) and uses the result as the plate's image fill. Next uses the arrow that points right (the export named `wood-plank-left`, see MANIFEST.md).
- **The signpost is the real art lettered with live text.** `derived/signpost.webp` at `sign-w` (280px), and each board's text in `ink-sign` at the percentages of `.gv-sign` in bundle.css (position, size and tilt about the box centre, which OpenPencil rotates about too), with the sign-scrim glow behind it (a blurred rectangle, layer blur 16) and the fit rule (`min(type size, board width / (characters x sign-glyph))`, a value past `sign-fit-chars` drops to `title-sm`, a long project name to two lines). The `no art` specimen is the same five boxes as flat wood plates in cream lettering, as `.gv-sign[data-art="failed"]` draws them. The sign's drop shadow is left out.
- Cards use `radius-md` (6px) rather than the CSS `corner-shape: bevel`, the documented iOS fallback; a bevelled plate would break the text-on-paper contrast chain. The printed double rule is a 1px inner ring.
- Inset shadows (rule, stamp, focus) are inside strokes and rings; the left accent edge of alerts, toasts, tags and InlineConfirm is a 4px bar.
- **The record control is a cream disc with a red ring**, as `.gv-rec__big` draws it (`surface` fill, an inset `stroke-focus` ring in `rec`, `shadow-ledge`), with a red square (`rec-size` x .34, `radius-sm`) to stop and a red dot (x .46) to start a memo; the calm halo behind it is `rec-ring` and is left out when paused. It was once drawn inverted (a red disc with a white glyph).
- **InlineConfirm's two buttons wrap** (`flex-wrap` and `justify-content: flex-end` in `.gv-confirm__actions`): where the pair does not fit one row (the md buttons of "Delete what was heard" in a 358px card) they sit on two right-aligned rows, 8px apart, as in Chromium; the admin pair (sm) and the recorder's lg pair keep their forms.
- **Where a line puts its glyphs (text engine against Chromium).** A browser puts the baseline `ascent - (content height - line height) / 2` below the top of the line box; the sheet's text engine puts it at `line height x ascent / content height`. They agree when the line is the font's own height and drift apart as it gets tighter, by `(content - line) x (ascent / content - 1/2)`: 41px for the 240/220 placard code, 7px for the 64/72 check, about 4px for Oswald 36/40 and under 2px for ordinary text. `lineMetrics` reads the ascent and descent from the font files (Chromium rounds both to whole pixels). Only the placard code and check are corrected, because only there the offset is visible: their row is as tall as the component's (257px: the QR starts 24px under it) and `floatCodes` lifts the two layers out of it onto the placard (absolute layers, because their line boxes hang 36px past the row and only a frame as big as the placard can hold them) and sets each where Chromium puts its baseline. Measured on the pixels against a Chromium screenshot of `TablePlacard` at scale 1: the glyph top of "A12" is at 133px in both, "K7" at 278 / 279, the PROJECT label at 643 in both, the slot rule at 708. The PlacardSheet thumbnails get the same correction at .36. Every other Oswald headline with a tight line (the room band, "Judges scan here", titles) sits up to about 4px higher in the sheet than in the browser; a text layer cannot hold both the glyph's place and a line box that fits its frame, so they are left as the engine draws them.
- **A scrolled screen (key screen 5).** The evaluate screen is taller than the phone: the sheet draws it scrolled to the recorder, which rests `space-4` above the dock. Each piece of the content is pinned to the phone at x = `space-4` (no wrapper frame: nesting) and drawn before the bars, so the app bar and the timer band cover what has gone up; after layout a measure hook stacks the pieces upward from the dock with `space-3` between them.
- **Durations in the Motion section** are bars at 1px per 2ms up to 1000ms; a longer one (`dur-retap`, `dur-toast`, `dur-undo`, `dur-pulse`, `dur-rec-pulse`, `dur-cant-find`, `demo-wait`) fills the 500px track and runs on in three dots, since 180,000ms cannot be drawn to scale. A value that is not a time (`demo-talk-rate`) has a 4px grey mark.
- Swatches are one rectangle with its own fill and its outline painted on top, so the paper swatch (`surface`) keeps its edge (a stroke on a parent frame is painted under its children, and a cream swatch on cream paper vanished).
- **Wide wood surfaces are bundle.css's `--gv-wood`**: the app bar, the action bar, the confirm bar, the print bar and the wood rows are a top-to-bottom gradient of the wood tokens (`wood-hi`, `wood` from 35% to 70%, `wood-deep`). The faint grain lines of the CSS are left out, and a gradient paint cannot bind its stops to variables, so these four stops are the one place a color is not a variable (they are token colors, resolved per theme). The planks are for buttons and signs only, as in the components.
- The painted ground (`derived/bg-sunset.webp`, `bg-night.webp`) is cover-fit under the `scrim` token on the key screens, as `.gv-ground` draws it.
- Specimens wider than a column (a 390px sheet in a 358px column) are centred on it and the gutters widen by the overhang, so nothing touches its neighbour; checked on the saved file (no overlaps, at least 32px between columns).
- Text widths are measured at export, with the real fonts loaded, and then saved: the generator exports before it saves and runs the OpenPencil 0.13.2 workaround for the Oswald GSUB bug (`opentype.js stringToGlyphs`).
- OpenPencil 0.13.2 saves each text layer's derived glyphs as one unwrapped line (no line breaks, no tracking), and its reader draws those baked glyphs as they are, so a reloaded `.fig` showed every paragraph as one long line. Before saving, the generator gives each text layer the glyphs the live renderer laid out (CanvasKit paragraph: wrapping, alignment, letter spacing, one outline per character so ligatures cannot shift the rest). If you edit a text layer in the editor, it re-lays out as usual.
- A text layer holds one style. Where a component runs a bold lead into the sentence (InlineConfirm: **"Revoke Sarah Kim?"** They are signed out...), the sheet puts the lead on its own line in the lead color.
- The `.fig` format does not keep `maxLines` or `textTruncation`, so a line that must show "one line, then an ellipsis" (a CompareCard description or notes line, the Removed row) is cut **on the string**: after layout the generator finds the longest prefix that fits and the layer holds `prefix…`. The saved file therefore reloads exactly as drawn.
- **`text-wrap: balance`** (bundle.css sets it on the primary button of a sheet or action bar, on question lines, card and sheet titles, the project name and the signpost label) is emulated the way the browser does it: the narrowest width that wraps to the same number of lines, with the line breaks written into the layer's text. OpenPencil wraps greedily, which left the consent button as "EVERYONE AGREED ·" over "START"; it now reads "EVERYONE" over "AGREED · START" like the component.
- **Brand SVGs** are imported as one frame of vectors. OpenPencil ignores `clip-path`, so a frame whose export clips to its own artboard (a `<clipPath>` rect the size of the viewBox, as in `longhorn-logo-alt.svg`) is made a clipping frame: the art no longer pokes out of its tile.
- A text layer in a frame without auto layout is never re-measured and keeps a 100px default box, so such a label gets an explicit one-line height (the "Stop" label under the record disc); everything else with text sits in an auto-layout frame. An empty field draws no empty text layer.
- A layer the generator adds after the first measure (the placard fit note, a Table talk caption note) is measured over two more passes, and the measuring loop runs up to 8 passes, until page heights stop moving.
- The PlacardSheet thumbnails are the real placard drawn at .36; text that would be under 12px at that scale (the footer, the Project label, the how-to line) is left out of them, since they are a picture of a printed page.
- The print thumbnails, the QR and the sheriff star seal are not Figma art: the QR is a labelled placeholder (finder squares and seeded noise, not scannable); the Round 1 sheriff star is the `.gv-star` polygon from bundle.css (a brass six-point star, a gold disc, a wood-deep ring, the check), because `MANIFEST.md` records no star or rosette art; the shadow tiles' star, rosette and card are illustrations of the shadow tokens.
- Two OpenPencil quirks to know when reading the sheet: the sheet's text engine draws a double hyphen as one dash, so notes avoid CSS variable names such as `--focus`; `op eval` prints only what the code `return`s.
